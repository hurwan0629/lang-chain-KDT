ASGI 서버 인터페이스에 맞춰진 fastapi의 비동기 및 워커 작업과 동기 작업을 따로 분리해서 하는 연습을 합니다.

데이터베이스는 컨테이너로 띄워서 BaseModel, alembic 마이그레이션, BaseModel 을 이용해보고

페이지는 여유가 되면 React를 사용해보려 합니다.

또한 프로세스의 진행 (여러 계층/역할을 자연스럽게 작업을 진행하는 역량을 강화하는 연습)

## 2. 프로젝트 설계
우선 해당 프로젝트의 주제는 사용자가 작업을 서버에 제출하면 서버가 다양한 방식으로 작업을 처리하는 API서버로 만들려 합니다.

넣을 기능으로는

- ai 작업 요청하기
  - 텍스트를 분석해서 어떤 카테고리인지, 요약해줄지 같은거 작성해주기
    - 해당 작업은 서버에 직접 코드를 작성하지 않고 다른 모듈에서 수행하기 (이를 통해서 외부/로컬 ai 차이 구분해보기)

## 3. [2026-07-24 17:34:20] 프로젝트 구조 잡기
현재 프로젝트 구조를 먼저 잡아보았습니다.

일단 프로젝트에서 비동기/프로세스/스레드 사용 작업을 좀 나눠보려고 합니다.

일단 존재할 Task의 종류는
- Task 생성하기
- Task 조회하기 (등록, 진행중, 완료)
- Task 종류
  - asyncIO 작업
  - blocking 작업 (asyncio 막는 작업)
  - thread pool 작업 (스레드를 생성해서 하는 작업)
  - AI 작업
- Task 실행 결과 조회

으로 분류할 수 있습니다.

실제로 하는 작업의 경우에는
1. url을 받아서 외부 api 여러개 써보기 (동기방식: requests, 비동기 방식: httpx/asyncio.gather() 모두 사용해보기)
2. 텍스트에서 총 글자 수, 총 단어 수, 가장 많이 등장한 단어, 암ㅎ화 등 계산해서 돌려주기 (cpu 작업)
3. cpu를 이용해서 특정 숫자 미만의 최대 소수 찾기
4. ai 텍스트 분석하기 (api는 io, 로컬은 cpu/gpu)

또한 위 작업들에서 걸린 시간과 작업 상태, 스레드 상태, asyncio 루프 상태, cpu/gpu 사용률 등을 보여주게 하려고 합니다.

## [2026-07-24 20:34:43] 모니터용 서버도 만들기로 결정
집오는 길에 생각해봤는데 블로킹 요청이나 메인 프로세스 cpu 작업 요청이 메인 서버를 막아버리면 서버 상태 요청에 대해 응답할 수 없기 때문에 redis와 모니터링 서버를 함께 올려서 메인 서버가 작업하기 전에 redis에 작업 내용을 올리게 하여 모니터링 서버가 서버 상태에 대해 응답하게 설정하기로 하였습니다.

또한 메인 서버에 대한 `작업 등록 요청`과 `작업 실행 요청`을 분리하여 잘 등록이 되어있는지와 실행이 되었는지 등을 확인 가능하게 구조를 잡으려 합니다.

### 최종
1. url을 대신 보내주는 작업 (io 대기)를 [asyncio 비동기 / 스레드풀 비동기 / 동기] 식으로 보내서 작업을 [생성/시작/결과/상태확인] 을 할 수 있게 하기
2. 문서를 주면 암호화를 몇번돌려서 주기(동기 작업)을 [asyncio/스레드풀/동기] 방식으로 보내보기
3. ai 작업을 요청해보기 (api/local 선택 가능), 이것도 동일하게 위 3가지 방식으로 요청 가능하게 하기
```
HTTP_FETCH
├─ DIRECT_SYNC
├─ THREAD_POOL
└─ ASYNC_IO


HASH_WORK
├─ DIRECT
├─ THREAD_POOL
└─ PROCESS_POOL


AI_ANALYSIS
├─ REMOTE
│   ├─ DIRECT_SYNC
│   ├─ THREAD_POOL
│   └─ ASYNC_IO
│
└─ LOCAL
    ├─ DIRECT
    ├─ THREAD_POOL
    └─ PROCESS_POOL
```
