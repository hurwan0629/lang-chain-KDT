컴퓨터의 숫자의 표현 방식을 다채롭게 알아보았습니다.

# 개요
저희는 개발 도중 여러 연산자를 사용하게 됩니다. 
이때 대부분의 프로그래밍 언어에서는 빠른 숫자의 연산을 하기 위해, 그리고 효율적인 공간 활용을 위한 숫자의 표현 방식을 사용합니다.

# 정수
사람은 0~9까지의 숫자를 사용하는 10진법을 사용하지만 컴퓨터는 0과 1만을 사용하는 2진법을 사용합니다. 
이때 컴퓨터가 사용하는 방식은 크게 2가지가 있는데요
- 1의 보수: 음수를 표현할 때 양수의 비트를 전부 뒤집는 방식
- 2의 보수: 1의 보수의 표현방식에 1을 더하는 방식 (현대의 대부분의 컴퓨터)
이를 한번 순서대로 자세히 알아보겠습니다. 
## 1의 보수
1의 보수는 앞에서 설명하였듯 음수를 표현할 때 양수의 비트를 전부 뒤집는 방식입니다.

예를 들어 8비트에서 `5`를 표현한다면 `0000 0101`형태가 만들어집니다.
이때 `-5`를 표현하고 싶은 경우에는 위의 값을 반전시켜 `1111 1010`형태로 표현하는 방식입니다.

이때 음수와 양수를 나누기 위하여 **부호가 있는 정수**(Signed Integer)을 표현할 때에는 첫번째 비트를 통해 양수(`0`)와 음수(`1`)를 표현합니다.
**부호가 없는 정수**(Unsigned Integer)의 경우에는 양수로만 처리됩니다.

이를 통해 8비트의 경우 1의 보수를 통해 `-127`~`127`을 표현할 수 있게 됩니다.

**하지만** 1의 보수는 0을 표현하는 방식이 `1111 1111`과 `0000 0000`으로 하나의 숫자를 동시에 차지하는 문제가 존재하였습니다. 이 때문에 등장한 방식이 2의 보수입니다.

## 2의 보수
2의 보수는 간단합니다.
양수에서 음수로 바뀔 때 1의 보수의 방식을 그대로 사용하되 `1`을 더해주는 방식입니다.

예를 들어서 동일하게 `5`를 표현하는 `0000 0101`에서 2의 보수 방식으로 `-5`를 표현하기 위해서는 `1111 1010`에 `1`을 더한 값인 `1111 1011` 형태로 표현을 하게 됩니다. 헷갈릴 수 있기 때문에 1바이트의 표현 범위별 표현을 표로 그려보겠습니다.

| 순서 | 나타내는 값 |
| ---: | ---: |
| 0000 0000 (0) | 0 |
| 0000 0001 (1) | 1 |
| ... | ... |
| 0111 1111 (127) | 127 |
| 1000 0000 (128) | -128 |
| 1000 0001 (129) | -127 |
| ... | ... |
| 1111 1111 (255) | -1 |

이러한 방식을 통해 빈틈 없이 표현식을 활용할 수 있었으며 연산에도 그저 두 값을 더하기만 하면 음수와 양수 사이의 계산까지 가능한 형태가 되었습니다.

### 모듈로 연산을 노린 2의 보수 설계
2의 보수는 시계의 원리인 **자릿수가 넘치면 버리는 성질**을 이용하였습니다.
따라서 순서대로 빈틈없이 값을 `0`~`127`, `-128`~`-1`을 나타내게 하였으며 이를 통해 `-1`을 더하기 보다는 `255`를 더하는 방식을 사용하였습니다. 이 때문에 음수가 `-1`이 아닌 `-128`부터 시작하게 설계되었습니다.
이 덕분에 `-1`과 `1`의 합이 `1111 1111`과 `0000 0001`의 합연산을 통해 `0000 0000`이 나올 수 있습니다.

# 소수
소수의 경우에도 정수의 표현과 같이 수학적 고려가 들어간 설계가 되어있습니다.
소수점의 표현도 크게 2가지가 존재합니다.
- 고정소수점: 1바이트 기준 소수점과 정수부의 자릿수를 지정하여 표현하는 방식입니다.
- 부동소수점: `[부호] [지수] [가수]` 표현을 통해 소수점을 나타내는 방식입니다.
## 고정소수점
먼저 말할 부분은 고정소수점은 현대 컴퓨터에서 많이 쓰이지 않는 방식입니다.

예를 들어 1바이트를 `[4자리 정수].[4자리 소수]`로 나눈다고 해보겠습니다.
이는 2의 보수 개념을 그대로 채택하여 
`2^3, 2^2, 2^1, 2^0, 2^-1, 2^-2, 2^-3, 2^-4`형태로 표기하는 방식입니다.

하지만 이는 소수 및 정수 부분의 길이를 고정시켜놓아 단순하지만 공간 활용을 효율적으로 못하는 구조가 되었습니다.

## 부동소수점
이를 해결하기 위해 소수점 위치를 바꿀 수 있는 **부동소수점**이 생기게 되었습니다.
사람의 10진법을 예로 들면 `123000`은 `123 * 10^3` 형태로 표현이 가능하듯, 2진법에서 또한 같은 방식으로 `110.01`을 `2^2 * 1.1001` 형태로 표현이 가능합니다. 그리고 해당 숫자는 32비트 기준 `[0] [1000 0001] [100100...]` 으로 표현이 됩니다.
여기에서 `[0]`은 양수, `[1000 0001]`은 2에 127을 더한 값인 129를 표현한 값입니다. (-127까지 표현하기 위한 방식) `[100100...]`은 가수의 고정 길이인 23비트를 표현한 것으로 `1.1001`에서 1을 제외한 값입니다.

### 이진법이기에 발생하는 연산 문제
정말 유명한 케이스로 `1.1 + 0.1 != 1.2`인 케이스가 존재합니다. 이는 부동소수점이 정확하게 소수를 표현하는 것이 아닌 2진법으로 나눠서 표현하기 때문입니다.

`1.1`은 `[0] [0111 1111] [0001 1001 1001 1001 1001 101]`으로 가수 부분이 `1001`으로 무한히 반복됩니다.
`0.1`은 `[0] [0111 1011] [1001 1001 1001 1001 1001 101]`으로 동일하게 무한 반복됩니다.
이 때문에 이진수를 합하여 
  1.00011001100110011001101  (1.1)
+ 0.00011001100110011001101  (0.1)
를 통해 무한 소수의 뒷부분이 생략되며 뒷부분이 표현되지 않는 문제가 발생하여 예상 외의 결과가 나오게 되는 문제가 있습니다.

**인상적인 사실**: 실제로 부동 소수점 연산 오차로 인해 **뱅쿠버 증권거래소 주가 지수 오류(1982)**라는 22개월동안 지수가 실제보다 낮게 표시된 문제가 있었습니다.

# 0과 1만 들어올 수 있는 공간을 가진 CPU가 긴 숫자 표현을 처리하는 방식
이렇게 여러 종류의 숫자 표현식을 알아보았는데 제가 느꼈던 의문점인 어떻게 이런 동적인 데이터 형태를 순간순간 회로만을 이용하는 CPU가 알지? 라는 생각을 하였었습니다.

이에 대한 정답은 CPU가 비트를 통해 아는 것이 아닌 문맥을 통해 `변수의 타입`, `CPU 명령어`, `언어 규칙` 등을 알려주는 방식으로 실현이 됩니다.

예를 들어 `1111 1111`도 해석에 따라 `255`(일반 숫자) `-1`(2의 보수) 같이 여러 의미로 해석이 가능합니다. 이 문제는 타입 표기를 통해 해결이 됩니다. 프로그래밍 코드에서 저장된 타입에 따라 CPU가 비트를 다르게 해석하게 되며 그에 맞는 명령어를 가져오게 됩니다. 
참고로 파이썬에서는 `int`, `float` 등의 객체의 메타데이터를 런타임 시점에 데이터의 형태를 해석하여 실행하게 됩니다.

## IEEE 754 표준이란 무엇인가? 
IEEE는 전기, 전자, 컴퓨터, 통신 분야의 국제적인 학회/기술 단체로 내부적으로 IEEE-SA라는 Standards Association (표준 협회)가 존재합니다. 여기에서 여러 기술 분야에 대한 표준을 개발합니다.
그중에서 32비트, 64비트 부동소수점은 IEEE 754 표준으로 이는 **실수 계산 전반**을 결정합니다.
- 부동 소수점 저장 형식: `[sign] [exponent] [fraction/mantissa]`
- 32비트 float: 단정도, single precision `[1] [8] [23]`길이의 비트
- 64비트 double: 배정도, double precision `[1] [11] [52]`길이의 비트. (이건 지수부에 1023을 더합니다. 11비트 = 0~2047 = `-1023`~`1024`)
- 반올림 방식: 가장 가까운 값으로 반올림 등
- 특수 값: +∞, -∞, NaN, +0, -0
- 아주 작은 수 처리
- 연산 규칙
등을 처리합니다.

추가적으로 `binary [16 | 32 | 64 | 128]`, `decimal [32 | 64 | 128]`(10진법 부동소수점) 등이 존재합니다.
## 부동소수점 오차는 실제 개발에서 어떤 문제를 발생시키는가?
앞에서 작은 계산 값 오류 (하지만 치명적일 수 있음)을 낸다고 하였지만 이외에도
- 비교 오류
- 누적 오차 (점점 오차가 쌓임)
- 무한루프 (실수값이 정확히 목표에 도달하지 못함)
- 데이터 처리 오류 (그룹화, 정렬 기준이 이상해짐)
- AI/과학 계산 오류 (`inf`, `NaN`, 언더플로우, 오버플로우)
등이 존재합니다.

# 금융/게임/AI 분야에서 소수 오차를 어떻게 처리하는가?
실제 금융/게임/AI에서는 `float` 대신에 `Decimal` 타입을 사용합니다. 
`Decimal`은 **10진수 문자열** 기반으로 수를 표현하여 인자로 `string`를 주어야합니다. (숫자를 주면 오차값을 만들 수 있습니다.)

### `Decimal`의 연산 방식
연산을 할 때 결국 `float`와 동일한 문제가 생기지 않을까 했지만 다른 방식으로 돌아가는 것을 확인했습니다.
예를 들어 `Decimal("12.90")`은 내부적으로
```
sign = 0
coefficient = 1290
exponent = -2
```
와 같이 설정이 되어 `(-1)^sign × coefficient × 10^exponent`와 같은 형태로 해석이 된다고 합니다.

따라서 계산을 할 때에도 `exponent`를 맞추어 더하던가 그냥 곱하던가, `coefficient`와 `sign`도 정수 형태로 정상적인 계산이 가능합니다.

### `Decimal`을 사용해도 조심해야할 점
`Decimal`은 무한소수는 어떻게 처리가 안되기 때문에 어느정도 타협을 하거나 아예 분자&분모 식으로 저장을 하는 것도 방법이 될 수 있을 것 같습니다.

추가로 `Epsilon`이라는 방식을 통해 미세한 차이는 동일하게 간주하는 방식을 채택하기도 한다고 합니다.

이를 한번 순서대로 자세히 알아보겠습니다.

1의 보수

1의 보수는 앞에서 설명하였듯 음수를 표현할 때 양수의 비트를 전부 뒤집는 방식입니다.

이때 음수와 양수를 나누기 위하여 부호가 있는 정수(Signed Integer)을 표현할 때에는 첫번째 비트를 통해 양수(0)와 음수(1)를 표현합니다.

부호가 없는 정수(Unsigned Integer)의 경우에는 양수로만 처리됩니다.

이를 통해 8비트의 경우 1의 보수를 통해 -127~127을 표현할 수 있게 됩니다.

하지만 1의 보수는 0을 표현하는 방식이 1111 1111과 0000 0000으로 하나의 숫자를 동시에 차지하는 문제가 존재하였습니다. 이 때문에 등장한 방식이 2의 보수입니다.

2의 보수

2의 보수는 간단합니다.

예를 들어서 동일하게 5를 표현하는 0000 0101에서 2의 보수 방식으로 -5를 표현하기 위해서는 1111 1010에 1을 더한 값인 1111 1011 형태로 표현을 하게 됩니다. 헷갈릴 수 있기 때문에 1바이트의 표현 범위별 표현을 표로 그려보겠습니다.

순서 나타내는 값
0000 0000 (0) 0
0000 0001 (1) 1
... ...
0111 1111 (127) 127
1000 0000 (128) -128
1000 0001 (129) -127
... ...
1111 1111 (255) -1

이러한 방식을 통해 빈틈 없이 표현식을 활용할 수 있었으며 연산에도 그저 두 값을 더하기만 하면 음수와 양수 사이의 계산까지 가능한 형태가 되었습니다.

모듈로 연산을 노린 2의 보수 설계

2의 보수는 시계의 원리인 자릿수가 넘치면 버리는 성질을 이용하였습니다.

따라서 순서대로 빈틈없이 값을 0~127, -128~-1을 나타내게 하였으며 이를 통해 -1을 더하기 보다는 255를 더하는 방식을 사용하였습니다. 이 때문에 음수가 -1이 아닌 -128부터 시작하게 설계되었습니다.

이 덕분에 -1과 1의 합이 1111 1111과 0000 0001의 합연산을 통해 0000 0000이 나올 수 있습니다.

소수

소수의 경우에도 정수의 표현과 같이 수학적 고려가 들어간 설계가 되어있습니다.

소수점의 표현도 크게 2가지가 존재합니다.

  • 고정소수점: 1바이트 기준 소수점과 정수부의 자릿수를 지정하여 표현하는 방식입니다.
  • 부동소수점: [부호] [지수] [가수] 표현을 통해 소수점을 나타내는 방식입니다.

고정소수점

먼저 말할 부분은 고정소수점은 현대 컴퓨터에서 많이 쓰이지 않는 방식입니다.

예를 들어 1바이트를 [4자리 정수].[4자리 소수]로 나눈다고 해보겠습니다.

이는 2의 보수 개념을 그대로 채택하여

2^3, 2^2, 2^1, 2^0, 2^-1, 2^-2, 2^-3, 2^-4

형태로 표기하는 방식입니다.

하지만 이는 소수 및 정수 부분의 길이를 고정시켜놓아 단순하지만 공간 활용을 효율적으로 못하는 구조가 되었습니다.

부동소수점

이를 해결하기 위해 소수점 위치를 바꿀 수 있는 부동소수점이 생기게 되었습니다.

사람의 10진법을 예로 들면 123000은 123 * 10^3 형태로 표현이 가능하듯, 2진법에서 또한 같은 방식으로 110.01을 2^2 * 1.1001 형태로 표현이 가능합니다. 그리고 해당 숫자는 32비트 기준 [0] [1000 0001] [100100...] 으로 표현이 됩니다.

여기에서 [0]은 양수, [1000 0001]은 2에 127을 더한 값인 129를 표현한 값입니다. (-127까지 표현하기 위한 방식) [100100...]은 가수의 고정 길이인 23비트를 표현한 것으로 1.1001에서 1을 제외한 값입니다.

이진법이기에 발생하는 연산 문제

정말 유명한 케이스로 1.1 + 0.1 != 1.2인 케이스가 존재합니다. 이는 부동소수점이 정확하게 소수를 표현하는 것이 아닌 2진법으로 나눠서 표현하기 때문입니다.

1.1은 [0] [0111 1111] [0001 1001 1001 1001 1001 101]으로 가수 부분이 1001으로 무한히 반복됩니다.

0.1은 [0] [0111 1011] [1001 1001 1001 1001 1001 101]으로 동일하게 무한 반복됩니다.

이 때문에 이진수를 합하여

  1.00011001100110011001101  (1.1)
+ 0.00011001100110011001101  (0.1)

를 통해 무한 소수의 뒷부분이 생략되며 뒷부분이 표현되지 않는 문제가 발생하여 예상 외의 결과가 나오게 되는 문제가 있습니다.

인상적인 사실: 실제로 부동 소수점 연산 오차로 인해 뱅쿠버 증권거래소 주가 지수 오류(1982)라는 22개월동안 지수가 실제보다 낮게 표시된 문제가 있었습니다.

0과 1만 들어올 수 있는 공간을 가진 CPU가 긴 숫자 표현을 처리하는 방식

이렇게 여러 종류의 숫자 표현식을 알아보았는데 제가 느꼈던 의문점인 어떻게 이런 동적인 데이터 형태를 순간순간 회로만을 이용하는 CPU가 알지? 라는 생각을 하였었습니다.

이에 대한 정답은 CPU가 비트를 통해 아는 것이 아닌 문맥을 통해 변수의 타입, CPU 명령어, 언어 규칙 등을 알려주는 방식으로 실현이 됩니다.

예를 들어 1111 1111도 해석에 따라 255(일반 숫자) -1(2의 보수) 같이 여러 의미로 해석이 가능합니다. 이 문제는 타입 표기를 통해 해결이 됩니다. 프로그래밍 코드에서 저장된 타입에 따라 CPU가 비트를 다르게 해석하게 되며 그에 맞는 명령어를 가져오게 됩니다.

참고로 파이썬에서는 int, float 등의 객체의 메타데이터를 런타임 시점에 데이터의 형태를 해석하여 실행하게 됩니다.
