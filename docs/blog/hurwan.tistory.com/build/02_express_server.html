1. 서버 시작 구조

실행 파일과 서버 구현 파일을 나누었다. app.js는 서버 모듈을 불러와 실행하고, server/main.js는 Express 앱의 설정과 라우트를 담당합니다. 

// app.js
const startServer = require("./server/main.js");

startServer();
// server/main.js
function main() {
  // Express 앱 설정
}

module.exports = main;
모듈을 불러오는 것과 실제로 실행하는 것을 분리하면 서버 함수를 다른 파일에서도 재사용하거나 테스트하기 쉽습니다.

2. Express 생성과 기본 설정

express()를 호출하면 요청 처리에 사용할 애플리케이션 객체가 만들어집니다. 경로를 안전하게 조합하기 위해 Node.js 기본 모듈인 path도 사용합니다. 

const express = require("express");
const path = require("path");

const app = express();
app.disable("x-powered-by");

x-powered-by를 끄면 응답 헤더에서 Express 사용 여부가 드러나지 않습니다. 이것만으로 보안이 완성되는 것은 아니며, 서버 기술 정보의 불필요한 노출을 줄이는 설정입니다.

3. 요청 본문을 객체로 변환하기

클라이언트가 보낸 본문은 형식에 맞는 파서 미들웨어를 거쳐야 req.body에서 편하게 사용할 수 있습니다. 

app.use(express.json());
app.use(express.urlencoded({ extended: true }));
  • express.json(): Content-Type: application/json인 본문을 JavaScript 객체로 변환합니다.
  • express.urlencoded(): id=abc&pw=1234 형태의 폼 데이터를 객체로 변환합니다.
  • extended: true: 중첩된 형태의 URL-encoded 데이터도 처리할 수 있게 합니다.
req.body는 Node.js가 자동으로 만드는 값이 아닙니다. 위와 같은 본문 파서가 요청 스트림을 읽고 생성합니다.

4. 미들웨어와 실행 순서

미들웨어는 요청과 응답 사이에서 등록된 순서대로 실행되는 함수입니다. 공통 로깅, 인증, 본문 파싱처럼 여러 라우트에서 반복되는 처리를 맡길 수 있습니다. 

app.use((req, res, next) => {
  console.log(req.method);
  console.log(req.url);
  next();
});

next()를 호출하면 다음 미들웨어로 이동합니다. 응답을 보내지도 않고 next()도 호출하지 않으면 요청 처리가 멈춘 채 대기하게 됩니다. 

app.use("/hello", (req, res, next) => {
  console.log("hello 경로의 미들웨어");
  next();
});

app.use("/hello/*left", (req, res, next) => {
  console.log("하위 경로:", req.params.left);
  console.log("쿼리 값:", req.query.param);
  next();
});
경로를 지정한 app.use()는 그 경로로 시작하는 요청에 적용됩니다. 마지막에는 반드시 응답을 보내는 라우트나 404 처리기가 필요합니다.

5. 정적 파일 제공

HTML, 브라우저 JavaScript, 이미지처럼 내용이 고정된 파일은 express.static() 미들웨어로 제공할 수 있습니다. 

app.use(
  "/resources",
  express.static(path.join(__dirname, "resources"))
);

예를 들어 resources/fox.png는 브라우저에서 /resources/fox.png로 요청할 수 있습니다. 디렉터리 경로를 요청하면 기본적으로 해당 디렉터리의 index.html을 탐색합니다.

6. EJS 템플릿 렌더링

Express의 설정 저장소에 뷰 엔진과 템플릿 디렉터리를 지정합니다. 같은 app.set()이라도 인자를 하나만 전달하면 설정값을 조회할 수 있습니다. 

app.set("view engine", "ejs");
app.set("views", path.join(__dirname, "views"));

console.log(app.get("views"));

res.render()는 템플릿에 데이터를 전달해 최종 HTML을 만듭니다. 

app.get("/ejs", (req, res) => {
  res.render("index", {
    name: "이름",
    age: 20
  });
});
<h1>어서오세요! <%= name %> 님!</h1>

<% for (let i = 0; i < 10; i++) { %>
  <p>당신의 나이는 <%= age %>입니다.</p>
<% } %>
  • <%= 값 %>: 값을 HTML에 출력합니다.
  • <% 코드 %>: 조건문이나 반복문 같은 JavaScript 코드를 실행합니다.

7. 경로와 HTTP 메서드에 따른 라우팅

app.get()처럼 HTTP 메서드별 처리기를 등록할 수 있습니다. 같은 경로에 여러 메서드를 연결할 때는 app.route()가 편리합니다. 

app.route("/users/:id")
  .get((req, res) => {
    res.send("사용자 조회");
  })
  .post((req, res) => {
    res.send("사용자 수정");
  })
  .delete((req, res) => {
    res.send("사용자 삭제");
  });
  • req.params.id: /users/10에서 경로 값 10
  • req.query: ?page=2처럼 URL 뒤에 붙는 쿼리 문자열
  • req.body: POST 요청 등에 포함된 본문 데이터

8. 요청 객체와 스트림

Express의 req는 Node.js의 http.IncomingMessage를 확장한 객체입니다. 메서드, URL, 헤더 같은 요청 정보와 함께 읽기 가능한 스트림의 성질도 갖습니다. 

req.on("data", chunk => {
  console.log("받은 데이터:", chunk);
});

req.on("end", () => {
  console.log("본문 수신 완료");
});

낮은 수준에서는 data 이벤트로 조각을 모으고 end에서 수신 완료를 확인합니다. 그러나 현재 서버처럼 express.json()을 먼저 등록하면 본문 파서가 요청 스트림을 이미 읽습니다.

하나의 라우트에서 express.json()과 직접 작성한 data/end 처리를 함께 실습하지 않는 편이 좋습니다. JSON 요청은 req.body로 확인하고, 원시 스트림 실습은 본문 파서를 거치지 않는 별도 경로에서 진행합니다. 
app.post("/about", (req, res) => {
  console.log(req.method);
  console.log(req.url);
  console.log(req.headers.host);
  console.log(req.body);

  res.json({
    message: "잘 받았습니다.",
    data: req.body
  });
});

9. 전체 요청 처리 흐름

브라우저에서 요청을 보내면 서버에서는 대략 다음 순서로 처리됩니다.

  1. 요청 수신
  2. 본문 파싱
  3. 공통 미들웨어
  4. 경로 탐색
  5. 라우트 실행
  6. 응답 생성
  7. 응답 전송
  8. 처리 종료
app.listen(8090, "127.0.0.1", () => {
  console.log("서버 실행 시작");
});

이 서버는 로컬 주소 127.0.0.1의 8090 포트에서 요청을 기다립니다. 개발 중에는 nodemon을 사용해 파일 변경 시 서버를 자동으로 재시작할 수 있습니다.

10. 핵심 정리

  • Express 앱은 미들웨어와 라우트를 등록해 요청 처리 흐름을 구성합니다.
  • 미들웨어는 등록 순서가 중요하며, 다음 단계로 갈 때 next()를 호출합니다.
  • 본문 파서가 요청 스트림을 읽어 req.body를 만듭니다.
  • express.static()은 이미지, HTML, 브라우저 JavaScript 같은 정적 파일을 제공합니다.
  • EJS는 서버의 데이터를 템플릿에 넣어 동적인 HTML을 생성합니다.
  • app.route()는 같은 경로의 여러 HTTP 메서드를 한곳에 모아 관리합니다.
  • 모든 요청은 최종적으로 응답을 보내거나 다음 처리기로 넘겨야 합니다.
