스케줄링의 단계

운영체제의 스케줄링... 이전까지는 그냥 적당히 프로세스의 순서를 지정해 주는 것일 뿐이라고 알고 있었는데 이렇게까지 심오한 내용인 줄은 몰랐습니다.
일단 스케줄링에는 단계가 존재하였습니다.

장기 스케줄링(작업 스케줄링)

디스크의 작업 중 어떤 작업을 메모리에 올릴지 결정하게 됩니다.

이는 프로세스를 밀리초 단위로 할당해 주는 일반적인 (단기) 스케줄링과 다르게 분 단위와 크거나 작은 더 큰 단위로 지정해 주는 간격이 생기게 됩니다.

중기 스케줄링(스와핑 스케줄링)

메모리의 프로세스를 잠시 빼거나 다시 넣어 줍니다. 단기와 장기 스케줄링의 중간 정도의 주기를 가집니다.

단기 스케줄링(CPU 스케줄링)

이전까지 제가 알던 스케줄링의 유일한 종류입니다.

작업(CPU의 할당)을 원하는 프로세스에 대해서 자원을 할당해 줍니다. 이를 디스패치라고 하며, 평균적인 대기 시간을 줄이고, 기아 상태의 프로세스를 줄이며, 컨텍스트 오버헤드가 많지 않은 방식을 지향하게 됩니다.

스케줄링의 방식

선입 선처리

First Come First Served라고 하는 방식으로 먼저 온 프로세스를 끝날 때까지 실행시켜 주는 방식입니다. 이는 매우 간단하지만 오래 걸리는 작업이 짧은 작업들이 시행되지 못하게 하는 경우를 많이 발생시킬 수 있으며, 대화형 시스템이 원하는 특성인 빠른 응답에 반하는 특성을 가집니다.

최소 작업 우선

Shortest Job First라는 방식으로 실행 시간이 가장 짧은 작업부터 실행하는 방식입니다.

이는 선점과 비선점 실행이 모두 가능하며 평균 대기 시간을 짧게 할 수 있지만 짧은 작업들이 연속해서 들어오면 긴 작업의 대기가 길어질 수 있습니다.

선점형의 경우에는 남은 시간이 짧은 프로세스를 실행해 주며 이를 최소 잔여 시간 우선 스케줄링이라고 부릅니다. 이는 평균 대기 시간과 평균 반환 시간을 짧게 하지만 문맥 교환 비용이 들기 때문에 항상 좋다고는 볼 수 없습니다.

우선순위 스케줄링

최소 작업 우선 스케줄링은 일반적인 우선순위 스케줄링의 구현 방식 중 하나입니다.

우선순위 스케줄링은 동일한 프로세스들은 선입 선처리 순서로 스케줄링하며, 프로세스 버스트(실행 시간)의 역을 통해 우선순위를 산출합니다. 이에 따라 우선순위가 높을수록 먼저 실행하게 되며 높은 우선순위가 끝나야 다음 우선순위 큐를 실행할 수 있게 됩니다.

이 또한 동일하게 선점 또는 비선점이 가능합니다.

우선순위 스케줄링 알고리즘의 주요 문제인 무한 대기와 기아의 경우에는 에이징이라는 우선순위가 낮은 프로세스에 시간이 지남에 따라 점점 우선순위를 높여 주는 방식으로 해결이 가능합니다.

라운드 로빈 스케줄링

일반적으로 저희가 아는 라운드 로빈과 동일하게 일정량의 규정 시간량 또는 시간 할당량을 주는 방식입니다. 이는 항상 선점형 스케줄링입니다.

여기에서 중요한 것은 q(시간 할당량)로, q의 크기가 너무 크면 선입 선처(FCFS)리 스케줄링과 거의 같아지며 너무 작은 경우에는 문맥 교환 비용이 거대해지게 됩니다.

이는 기아가 잘 생기지 않으며 빠른 응답이 가능한 장점이 존재하지만 하드웨어에 타이머가 필요하며 q의 설정을 잘해 주어야 하는 단점이 존재합니다.

다단계 큐 스케줄링

MultiLevel Queue 스케줄링으로 각 작업을 서로 다른 묶음으로 분류할 수 있을 때 사용합니다. 예를 들어 작업을 포그라운드와 백그라운드로 분류하여 두 유형의 일반적인 반응 시간이 다름을 이용하여 다르게 스케줄링하는 방식입니다.

여기에는 각 큐의 묶음에 우선순위를 절대적으로 지정하여 큐를 모두 써야 다음 우선순위 큐의 작업을 실행 가능하게 하는 방식입니다.

여기에는 작업의 우선순위에 따라 다른 비율의 라운드 로빈 방식을 사용하여 높은 우선순위에는 70%를, 낮은 우선순위에는 30%를 할당하는 방식을 사용할 수 있습니다.

다단계 피드백 큐 스케줄링

다단계 큐 스케줄링은 작업이 시스템에 들어가면 한 큐에서만 고정되어 실행됩니다.

이런 융통성의 부족에 의해 예외 사항에 유연하게 대처할 수 없음에 따라 작업이 큐 사이를 이동할 수 있게 한 방식의 스케줄링 방식입니다.

또한 긴 작업이 규정 시간을 다 사용할 때마다 다음번에 할당해 주는 규정 시간을 늘려 주는 방식을 이용할 수 있습니다.

HRN 스케줄링

최소 작업 우선 스케줄링의 약점인 긴 작업에 대해서 대기 시간이 길어지는 것을 방지하기 위해 응답률 = (대기 시간 + 서비스 시간) / 서비스 시간의 공식을 이용하여 오래 기다릴수록 우선순위가 높아지는 방법입니다.

다중 프로세서 스케줄링

프로세서가 여러 개면 스케줄링 문제가 복잡해짐에 따라 하나의 큐를 여러 프로세서가 공유하는 방식(대칭형 다중 처리)과 하나의 프로세서(비대칭형 다중 처리)가 다른 프로세서에게 프로세스들을 할당해 주는 방식이 존재합니다.

대칭형 다중 처리(SMP)는 동시성 문제를 고려해야 하고, 비대칭형 다중 처리는 마스터 프로세서의 부담이 커진다는 단점들이 존재합니다.
