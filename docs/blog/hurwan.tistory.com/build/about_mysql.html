뷰

뷰(VIEW)는 SELECT 문의 결과를 테이블처럼 조회할 수 있게 만든 데이터베이스 객체입니다.

CREATE VIEW member_view AS
SELECT
    member_pk AS pk,
    member_id AS id,
    member_hobby AS hobby
FROM member;

뷰는 일반적으로 조회 결과 자체를 별도로 저장하지 않고, 저장된 SELECT 문을 실행해 원본 테이블의 현재 데이터를 보여 줍니다. 따라서 원본 테이블의 데이터가 변경되면 뷰의 조회 결과에도 반영됩니다.

다만 원본 테이블에 새로운 컬럼을 추가한다고 해서 기존 뷰에 그 컬럼이 자동으로 추가되는 것은 아닙니다. 뷰가 참조하는 컬럼이나 테이블을 삭제하거나 이름을 변경하면 조회 오류가 발생할 수 있습니다.

  • 복잡한 쿼리를 단순한 인터페이스로 제공할 수 있습니다.
  • 자주 사용하는 쿼리를 재사용할 수 있습니다.
  • 필요한 컬럼만 노출하고 뷰에 별도의 권한을 부여하여 접근 범위를 제한할 수 있습니다.
컬럼 별칭(alias)은 이름을 바꾸어 보여 주는 기능일 뿐, 그 자체로 보안을 제공하지는 않습니다. 원본 테이블의 권한을 제한하고 뷰에 적절한 권한을 부여해야 합니다.

DDL과 데이터베이스

DDL

DDL(Data Definition Language)은 데이터베이스의 구조와 객체를 생성하거나 변경하고 삭제하는 명령어입니다. 대표적으로 CREATE, ALTER, DROP이 있습니다.

DDL은 테이블과 데이터베이스 구조에 큰 영향을 줄 수 있으므로, 운영 환경에서는 영향 범위와 잠금 발생 여부 등을 확인한 뒤 실행해야 합니다.

CREATE DATABASE

CREATE DATABASE testdb
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_0900_ai_ci;

문자 집합(CHARACTER SET)은 문자를 저장하는 인코딩 방식을 지정하고, 콜레이션(COLLATE)은 문자열을 비교하고 정렬하는 규칙을 지정합니다.

utf8mb4는 문자 하나를 최대 4바이트로 표현할 수 있는 UTF-8 문자 집합입니다. MySQL의 utf8은 최대 3바이트만 사용하는 utf8mb3의 사용 중단 예정 별칭이므로 새로운 시스템에서는 utf8mb4를 사용하는 것이 좋습니다.

  • utf8mb4: 문자 집합
  • 0900: Unicode Collation Algorithm 9.0.0 기반
  • ai: 악센트를 구분하지 않음
  • ci: 대소문자를 구분하지 않음
SHOW VARIABLES LIKE 'character_set%';
SHOW VARIABLES LIKE 'collation%';
MySQL 8.4의 기본 문자 집합과 콜레이션은 utf8mb4와 utf8mb4_0900_ai_ci입니다. Docker 사용 여부가 문자 집합을 결정하는 것은 아니며, 버전과 이미지, 서버 및 클라이언트 설정에 따라 실제 값이 달라질 수 있습니다.

사용자와 권한

CREATE USER

MySQL 계정은 사용자 이름과 접속 호스트의 조합인 '사용자명'@'호스트'로 식별합니다.

CREATE USER 'app_user'@'localhost'
IDENTIFIED BY 'strong_password';

'app_user'@'localhost'와 'app_user'@'10.0.0.10'은 서로 다른 계정입니다.

CREATE USER 'app_user'@'192.168.%'
IDENTIFIED BY 'strong_password';

호스트 와일드카드는 LIKE 패턴처럼 일치하는 호스트를 허용하지만, MySQL 8.0.35부터 이 방식은 사용 중단 예정입니다. 최신 버전에서는 명시적인 호스트나 네트워크 범위 지정 방식을 검토하는 것이 좋습니다.

권한 부여와 회수

GRANT SELECT, INSERT, UPDATE
ON testdb.member
TO 'app_user'@'localhost';

GRANT SELECT
ON testdb.*
TO 'app_user'@'localhost';

데이터베이스의 모든 테이블은 testdb.*, 서버의 모든 데이터베이스에 대한 전역 권한은 *.*으로 표현합니다. ALL PRIVILEGES에는 GRANT OPTION이 포함되지 않습니다.

REVOKE SELECT, INSERT, UPDATE
ON testdb.member
FROM 'app_user'@'localhost';

DROP USER 'app_user'@'localhost';

권한을 확인할 때는 시스템 테이블을 직접 수정하지 말고 SHOW GRANTS를 사용하는 것이 좋습니다.

SHOW GRANTS FOR 'app_user'@'localhost';

mysql 시스템 스키마

MySQL은 계정과 권한 정보를 mysql 시스템 스키마에 저장합니다. mysql.user에는 일부 전역 권한 정보가 있지만, 데이터베이스 및 테이블 단위 권한, 역할, 동적 권한 등은 다른 시스템 테이블에도 저장됩니다.

테이블과 제약 조건

CREATE TABLE

CREATE TABLE member (
    member_id BIGINT AUTO_INCREMENT,
    email VARCHAR(255) NOT NULL,
    nickname VARCHAR(50) NOT NULL,
    balance DECIMAL(12, 2) NOT NULL DEFAULT 0.00,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (member_id),
    UNIQUE KEY uk_member_email (email),
    CHECK (balance >= 0)
);
  • INT, BIGINT: 정수
  • DECIMAL(M, D): 정확한 고정 소수점 수
  • CHAR(N): 고정 길이 문자열
  • VARCHAR(N): 가변 길이 문자열
  • TEXT: 큰 문자열
  • BLOB: 큰 이진 데이터
  • DATE, DATETIME: 날짜와 시간
  • JSON: JSON 문서

DECIMAL(M, D)에서 M은 전체 자릿수이고 D는 소수점 이하 자릿수입니다. MySQL에는 PostgreSQL의 JSONB 타입이나 표준 SQL 계열의 CLOB 타입이 없습니다.

주요 제약 조건

  • PRIMARY KEY: 각 행을 고유하게 식별
  • AUTO_INCREMENT: 숫자 값을 자동 증가
  • NOT NULL: NULL 저장 금지
  • UNIQUE: 중복 값 제한
  • DEFAULT: 값이 생략됐을 때 사용할 기본값
  • CHECK: 저장할 값이 조건을 만족하는지 검사
  • FOREIGN KEY: 관계와 참조 무결성을 정의

MySQL 8.0.16 이상에서는 CHECK 제약 조건이 실제로 적용됩니다. 그보다 오래된 버전에서는 문법을 허용하더라도 조건을 검사하지 않을 수 있습니다.

외래 키

CREATE TABLE orders (
    order_id BIGINT AUTO_INCREMENT,
    member_id BIGINT NOT NULL,
    PRIMARY KEY (order_id),
    CONSTRAINT fk_orders_member
        FOREIGN KEY (member_id)
        REFERENCES member (member_id)
        ON UPDATE CASCADE
        ON DELETE RESTRICT
);

CONSTRAINT fk_orders_member는 제약 조건의 이름이고, FOREIGN KEY (member_id)는 현재 테이블에서 외래 키로 사용할 컬럼을 뜻합니다.

ALTER와 DML

ALTER TABLE

ALTER TABLE member
ADD COLUMN last_login_at DATETIME NULL;

ALTER TABLE member
MODIFY COLUMN nickname VARCHAR(100) NOT NULL;

운영 중인 큰 테이블을 변경하면 긴 실행 시간, 잠금, 추가 저장 공간 사용 또는 애플리케이션 호환성 문제가 발생할 수 있습니다. 실행 전에 DDL 알고리즘과 잠금 수준, 롤백 및 배포 계획을 확인해야 합니다.

DML

DML(Data Manipulation Language)은 테이블의 데이터를 조회하거나 변경하는 명령어입니다.

  • INSERT: 행 추가
  • SELECT: 데이터 조회
  • UPDATE: 행 수정
  • DELETE: 행 삭제

서비스에 따라 데이터를 즉시 삭제하지 않고 deleted_at이나 삭제 여부 컬럼을 변경하는 논리적 삭제를 사용하기도 합니다. 데이터 보존 정책과 개인정보 삭제 요건 등을 고려해 선택해야 합니다.

저장 엔진

MySQL은 플러그형 저장 엔진 구조를 사용합니다. MySQL 8.4에서 새 테이블의 기본 저장 엔진은 InnoDB이지만, MySQL이 내부적으로 오직 InnoDB만 사용하는 것은 아닙니다.

SHOW ENGINES;

InnoDB는 트랜잭션, 행 수준 잠금, 외래 키 및 장애 복구 기능 등을 지원하는 범용 저장 엔진입니다. 특별한 요구 사항이 없다면 일반적인 애플리케이션 테이블에는 InnoDB를 사용하는 것이 권장됩니다.
