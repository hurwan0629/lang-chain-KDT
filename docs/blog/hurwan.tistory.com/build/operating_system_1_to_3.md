# [그림으로 배우는 운영체제] 컴퓨터 시스템/운영체제 소개/프로세스와 스레드

> 2일 동안 책의 세 챕터를 읽으면서 새로 알게 된 내용과 주요 개념을 정리하기 위해 포스팅하였습니다. 기존에 알던 지식보다는 새로 알게 된 개념을 중심으로 글을 작성하였습니다.

## 컴퓨터 시스템의 소개

### 컴퓨터 하드웨어의 구성

우선 컴퓨터 하드웨어에는 **CPU**, **ALU**, **레지스터**, **버스**(시스템, 데이터, 주소, 제어)가 존재한다는 점은 알고 있었습니다.

이때 새로 알게 된 부분은 레지스터를 크게 두 종류로 구분할 수 있다는 점입니다.

- **사용자 가시 레지스터**: 프로그램의 명령어를 통해 값을 참조하거나 변경할 수 있는 레지스터
  - 데이터 레지스터
  - 누산기 (`ACC`)
  - 기준 주소 레지스터
  - 인덱스 레지스터
  - 스택 포인터 레지스터
- **사용자 불가시 레지스터**: 일반적인 프로그램에서 직접 다룰 수 없으며 프로세서의 상태와 제어를 관리하는 데 사용되는 레지스터
  - 프로그램 카운터 (`PC`)
  - 명령어 레지스터 (`IR`)
  - 메모리 주소 레지스터 (`MAR`)
  - 메모리 버퍼 레지스터 (`MBR`)

3장에서는 **스택 포인터**가 좀 더 자세히 다뤄졌습니다. 또한 **프로그램 카운터**도 자주 언급되었습니다. 물론 모두 중요한 레지스터입니다.

#### 프로세스의 명령어 실행 과정

프로세스가 실행될 때 CPU가 처리하는 명령어는 일반적으로 **`[연산 코드] [피연산자 또는 주소 지정 정보]`**로 구성됩니다. **직접 주소 지정 방식**에서는 명령어의 주소 필드가 피연산자의 유효 주소를 나타내고, **간접 주소 지정 방식**에서는 주소 필드가 유효 주소가 저장된 위치를 나타냅니다.

메모리에 접근할 때 **가상 주소**는 주소 변환 과정을 거쳐 **물리 주소**로 변환됩니다. 캐시는 주소를 일반적으로 **`[태그] [인덱스] [블록 오프셋]`**으로 나누어 캐시 적중 여부를 확인합니다. 캐시에 데이터가 없으면 하위 메모리 계층에서 데이터를 가져옵니다.

#### 사이클

프로세스가 실행되는 동안 CPU는 기본적으로 명령어의 **`인출 사이클`**과 **`실행 사이클`**을 반복합니다. 이 과정에서 버스와 레지스터를 이용하여 데이터를 이동하고 적재합니다.

**인출 사이클**에서는 `PC`(프로그램 카운터)에 저장된 주소를 `MAR`(메모리 주소 레지스터)로 보냅니다. 이후 해당 주소를 주소 버스에 전달하고, 메모리에서 읽은 명령어를 데이터 버스를 통해 `MBR`(메모리 버퍼 레지스터)로 가져온 뒤 `IR`(명령어 레지스터)에 전달합니다. 이때 제어 버스를 통해 메모리 읽기 등의 제어 신호를 전달합니다.

**실행 사이클**에서는 인출한 명령어를 해독하고, 그 결과에 따라 제어 신호를 발생시켜 명령어를 실행합니다.

**간접 사이클**은 간접 주소 지정 방식을 사용하는 명령어에서 피연산자의 유효 주소를 메모리로부터 가져오는 과정입니다.

**인터럽트 사이클**에서는 인터럽트가 발생했을 때 현재 프로그램을 나중에 재개할 수 있도록 `PC`와 상태 정보 등을 저장하고, **인터럽트 벡터**를 참조하여 해당 인터럽트 서비스 루틴으로 제어를 넘깁니다.

#### 인터럽트

**인터럽트**는 CPU가 현재 수행 중인 작업의 흐름을 잠시 중단하고 특정 사건을 처리하도록 요청하는 신호입니다. 인터럽트 요청 회선은 **단일 회선** 또는 **다중 회선**으로 구성할 수 있습니다. 단일 회선 방식에서는 CPU가 인터럽트를 요청한 장치를 식별하는 과정이 필요합니다. 다중 회선 방식은 장치 식별이 더 단순할 수 있지만 구현에 더 많은 물리적 자원이 필요합니다.

## 운영체제의 개념과 발전 목적

**운영체제**는 사용자 및 응용 프로그램과 하드웨어 사이의 인터페이스입니다. 운영체제의 주요 역할과 평가 기준은 다음과 같습니다.

- 조정자
- 자원 할당자 및 관리자
- 응용 프로그램과 입출력 장치 사이의 제어자
- 보안
- 효율성
- 처리량
- 지연/응답 시간
- 신뢰도
- 가용도

### 운영체제의 발전 과정과 유형

운영체제는 1940년대부터 발전해 왔다고 볼 수 있습니다.

- **1940년대**: 사용자가 순서를 기다렸다가 기계어로 작성한 프로그램을 직접 입력하여 사용
- **1950년대**: 일괄 처리 시스템을 통해 비슷한 작업을 한 번에 처리
- **1960년대**: 다중 프로그래밍과 시분할 시스템이 발전하고 고급 언어의 사용이 확대됨
- **1970년대**: 다중 모드, 장치 독립성 및 분산 처리 시스템이 발전함
- **1990년대**: 병렬 계산과 분산 계산이 발전하고 분산 컴퓨팅 환경이 확대됨
- **2000년대 이후**: 네트워크 기반 분산 시스템과 운영체제가 보편화되고, 가상화 기술과 모바일 및 임베디드 시스템이 발전함

### 주요 발전 순서

#### 1. 일괄 처리

작업 `A`, `B`, `C`, `D`를 운영자의 개입 없이 순서대로 처리할 수 있게 되었습니다. 이전에는 작업 `A`가 끝난 뒤 다음 사용자가 작업 `B`를 실행할 때까지 유휴 시간이 발생했습니다.

**버퍼링**을 통해 프로세서와 입출력 장치의 속도 차이를 완화했습니다. **스풀링**을 사용하면 디스크 등의 보조 기억 장치에 작업을 대기시킨 뒤 순차적으로 처리할 수 있어, CPU와 입출력 장치를 더 효율적으로 사용할 수 있습니다.

#### 2. 다중 프로그래밍/시분할/다중 처리/실시간 시스템

- **다중 프로그래밍**: 입출력 작업의 대기 시간 동안 다른 작업을 실행할 수 있게 함
- **시분할**: 각 프로세스에 **타임 슬라이스**라는 짧은 시간 단위로 CPU를 할당하여 여러 작업이 동시에 실행되는 것과 같은 효과를 냄
- **다중 처리**: 두 개 이상의 프로세서 또는 CPU 코어를 이용하여 여러 작업을 병렬로 처리함
- **실시간 시스템**: 정해진 시간 제약을 충족하도록 작업을 처리함. 요구되는 시간 제약의 엄격성에 따라 **경성 실시간 시스템**과 **연성 실시간 시스템**으로 나뉨

### 운영체제의 주요 특징

컴퓨터가 부팅되면 **BIOS** 또는 **UEFI 펌웨어**가 하드웨어를 초기화하고 **부트로더**를 실행합니다. 부트로더는 저장 장치에 있는 **운영체제 커널**을 메모리에 적재하고 실행합니다.

운영체제의 성능과 품질을 나타내는 대표적인 네 가지 지표는 다음과 같습니다.

- **신뢰도**: 고장 없이 얼마나 안정적으로 동작하는지 (`reliability`)
- **처리량**: 단위 시간 동안 처리하는 작업량 (`throughput`)
- **반환 시간**: 작업 제출부터 완료까지 걸린 전체 시간 (`turnaround time`)
- **가용도**: 필요할 때 시스템을 사용할 수 있는 정도 (`availability`)

## 프로세스와 스레드

실행 중인 프로그램을 **프로세스**라고 하며, 프로세스는 **사용자 프로세스**와 **시스템(커널) 프로세스** 등으로 구분할 수 있습니다.

프로세스에는 생성, 준비, 실행, 대기(블록), 종료 등의 기본 상태가 있으며, 일부 모델에서는 준비 중단과 대기 중단 상태를 추가로 구분합니다. CPU 할당을 기다리는 상태를 **준비 상태**, 입출력 완료나 특정 사건의 발생을 기다리는 상태를 **대기 상태**라고 합니다. **중단 상태**는 프로세스가 주기억 장치에서 보조 기억 장치로 옮겨져 실행 대상에서 일시적으로 제외된 상태를 뜻합니다. 운영체제가 준비 상태의 프로세스에 CPU를 할당하여 실행 상태로 전환하는 것을 **디스패치**라고 합니다.

### 프로세스의 관리

프로세스는 운영체제에서 **부모-자식 관계의 트리 형태**로 관리될 수 있습니다. 유닉스 계열 운영체제에서는 `fork()`로 부모 프로세스를 복제하여 자식 프로세스를 만들고, 필요하면 `exec()`로 자식 프로세스의 메모리 공간을 새 프로그램으로 교체합니다. 운영체제와 생성 방식에 따라 부모를 복제하지 않고 새로운 프로세스를 생성하기도 합니다.

### 스케줄링

프로세스가 생성되면 **PCB**(`Process Control Block`, 프로세스 제어 블록)가 만들어집니다. 운영체제는 PCB에 저장된 정보를 이용하여 프로세스의 상태를 관리하고 중단된 작업을 재개합니다. CPU 할당을 기다리는 프로세스들은 **준비 큐**에 들어가며, 스케줄링 정책에 따라 CPU를 할당받습니다.

### 스레드

프로세스 내부에는 더 작은 실행 단위인 **스레드**가 존재하며, 프로세스는 최소 하나의 스레드를 가집니다. 한 프로세스에 속한 스레드들은 **코드, 데이터, 힙 영역과 운영체제 자원** 등을 공유하지만, 각 스레드는 독립적인 **스택과 레지스터 문맥**을 가집니다. 각 스레드는 자신의 `PC`와 **스택 포인터**를 통해 실행 상태를 관리합니다.

### 스레드의 스케줄링

사용자 스레드와 커널 스레드의 매핑 방식에는 **다대일**, **일대일**, **다대다 모델**이 있습니다.

**다대일 모델**에서는 여러 사용자 스레드를 하나의 커널 스레드에 매핑합니다. 스레드 관리는 사용자 영역의 스레드 라이브러리가 담당하므로 효율적이지만, 하나의 스레드가 **블로킹 시스템 호출**을 수행하면 같은 프로세스의 다른 스레드도 실행하지 못할 수 있습니다. 또한 여러 CPU 코어에서 스레드를 병렬로 실행할 수 없습니다.

**일대일 모델**에서는 각 사용자 스레드를 하나의 커널 스레드에 매핑합니다. 각 커널 스레드는 운영체제의 스케줄링 대상이므로 병렬 실행이 가능하고, 한 스레드가 블로킹되어도 다른 스레드는 실행될 수 있습니다. 다만 스레드 생성과 문맥 교환에 드는 커널 오버헤드가 다대일 모델보다 클 수 있습니다.

**다대다 모델**에서는 여러 사용자 스레드를 같거나 더 적은 수의 커널 스레드에 다중화합니다. 사용자 영역에서는 스레드 라이브러리가 사용자 스레드를 관리하고, 커널은 매핑된 커널 스레드를 스케줄링합니다. 이 모델은 다대일과 일대일 모델의 장점을 절충할 수 있지만 구현이 복잡합니다.
