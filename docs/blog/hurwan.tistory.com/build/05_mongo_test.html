1. MongoDB의 데이터 구조

이전까지는 RDB만 사용했지만, 이번에는 대표적인 NoSQL 데이터베이스인 MongoDB를 사용하게 되었습니다.

MongoDB는 JSON과 유사한 BSON 형식으로 데이터를 저장합니다. SQL 데이터베이스의 테이블·행·열 대신 컬렉션과 문서를 사용하며, 각 문서에는 데이터를 식별하는 _id 필드가 자동으로 추가됩니다. 

{
  _id: ObjectId("..."),
  name: "hurwan",
  age: 20
}

2. 기본 문법

사용할 데이터베이스는 use 데이터베이스명으로 선택하고, 컬렉션의 메서드는 db.컬렉션명.메서드() 형태로 호출합니다.

  1. insertOne({}): 문서 하나를 삽입합니다.
  2. insertMany([{}, ...]): 여러 문서를 삽입합니다.
  3. find({ 조건 }, { 선택할 필드 }): 조건에 맞는 문서를 조회합니다. 중첩 필드는 { "person.age": 20 }처럼 점 표기법으로 접근합니다.
  4. updateOne({ 조건 }, { $set: { 수정 내용 } }): 조건에 처음 일치하는 문서 하나를 수정합니다.
  5. updateMany({ 조건 }, { $set: { 수정 내용 } }): 조건에 일치하는 모든 문서를 수정합니다.
  6. deleteOne({ 조건 }): 조건에 일치하는 문서 하나를 삭제합니다.
  7. deleteMany({ 조건 }): 조건에 일치하는 여러 문서를 삭제합니다.

조회 조건

// age가 0이고 name이 "hurwan"인 문서
db.users.find({ age: 0, name: "hurwan" })

// 비교 및 포함 조건
db.users.find({ age: { $eq: 20 } })
db.users.find({ age: { $gt: 20 } })
db.users.find({ age: { $gte: 20 } })
db.users.find({ age: { $lt: 20 } })
db.users.find({ age: { $lte: 20 } })
db.users.find({ age: { $in: [20, 21, 22] } })
db.users.find({ age: { $nin: [20, 21, 22] } })

하나의 조건 객체 안에서 필드를 쉼표로 구분하면 기본적으로 AND 조건으로 처리됩니다.

정렬, 건너뛰기, 개수 제한

db.users
  .find({})
  .sort({ age: 1 })  // 1: 오름차순, -1: 내림차순
  .skip(10)
  .limit(5)

수정 연산자

$set 값 설정 또는 필드 추가
$unset 필드 삭제
$inc 숫자 증가 또는 감소
$push 배열에 값 추가
$pull 배열에서 값 제거
$addToSet 중복 없이 배열에 추가

이외에도 집계 파이프라인과 컬렉션 간 조인 등의 기능을 사용할 수 있습니다.

3. 저장 구조와 성능

MongoDB는 함께 사용하는 데이터를 하나의 문서 안에 넣는 구조에 강합니다. 관련 데이터를 문서에 함께 저장하면 여러 테이블을 조인하지 않고 한 번에 읽을 수 있습니다.

BSON은 JSON 파일 하나를 디스크에 그대로 저장하는 방식이 아닙니다. 데이터베이스 엔진이 문서 저장 형식을 페이지 또는 블록 단위로 관리하고, 별도의 인덱스 구조도 함께 유지합니다.

컬렉션에서 인덱스로 지정한 필드는 별도의 인덱스 구조로 관리되므로 조건 검색 속도를 높일 수 있습니다. 다만 인덱스는 추가 저장 공간과 쓰기 비용을 사용합니다.

4. $lookup으로 조인하기

MongoDB에서도 집계 파이프라인의 $lookup을 사용하면 다른 컬렉션의 문서를 연결할 수 있습니다. 

db.orders.aggregate([
  {
    $lookup: {
      from: "users",
      localField: "userId",
      foreignField: "_id",
      as: "user"
    }
  }
])

위 집계를 실행하면 연결된 사용자 문서가 user 배열에 담깁니다.

{
  _id: ObjectId("order1"),
  userId: ObjectId("user1"),
  product: "keyboard",
  user: [
    {
      _id: ObjectId("user1"),
      name: "kim",
      email: "kim@test.com"
    }
  ]
}
  • orders 문서 읽기
  • userId 확인
  • users 문서 검색
  • user 배열에 추가

실행 계획과 인덱스를 이용해 조인하는 RDB와는 접근 방식과 기본 철학이 다릅니다. MongoDB에서도 연결 작업을 최적화할 수 있지만, 자주 함께 읽는 데이터는 한 문서에 두는 것이 기본적인 모델링 방향입니다.

5. Atlas와 연결하기

MongoDB Atlas는 MongoDB에서 제공하는 클라우드 데이터베이스 서비스입니다. 일반적인 복제 세트 구성에서는 주 서버 1개와 보조 서버 2개로 클러스터가 구성됩니다.

드라이버가 Atlas에 연결할 때 사용할 수 있는 URI 형식은 다음 두 가지입니다.

mongodb://...
mongodb+srv://...
  • mongodb://: 연결할 서버 주소와 포트 등을 URI에 직접 명시합니다.
  • mongodb+srv://: DNS의 SRV·TXT 레코드에서 연결 정보를 조회합니다.

Node.js나 VS Code에서 mongodb+srv:// 연결이 실패한다면 현재 네트워크의 DNS가 SRV·TXT 조회를 지원하는지 확인합니다. 공용 DNS를 사용해 확인한 뒤에도 해결되지 않으면 Atlas가 제공하는 mongodb:// 연결 문자열을 사용할 수 있습니다.

6. 핵심 정리

  • MongoDB는 데이터를 BSON 문서로 저장하고 컬렉션으로 관리합니다.
  • 기본 CRUD는 insert, find, update, delete 계열 메서드로 수행합니다.
  • 인덱스는 조회를 빠르게 하지만 저장 공간과 쓰기 비용이 추가됩니다.
  • $lookup으로 컬렉션을 연결할 수 있지만, 함께 읽는 데이터는 한 문서에 두는 방식이 MongoDB에 더 자연스럽습니다.
  • Atlas 연결 시 mongodb+srv://는 DNS의 SRV·TXT 레코드를 사용합니다.
