# if문의 비용

`if`문 자체는 `if` 다음의 연산을 수행하여 결과(`boolean`)에 따라 다음 코드 수행 위치를 이동시키는 것이 전부입니다.

여기에서 `if`문 뒤에 수행하는 연산을 제외하면 `if`문 자체에 대한 오버헤드는 거의 없다고 볼 수 있습니다.

import timeit

# 반복 횟수 
N = 10_000_000

baseline = timeit.timeit(
    "pass",
    number=N
)

# x = True인 경우에 대한 1000만번 실행 시간
if_true_time = timeit.timeit(
    """
if x:
    pass
""",
    setup="x = True",
    number=N
)

# x = False에 대한 1000만번 실행 시간

if x:
    pass
""",
    setup="x = False",
    number=N
)

print("pass만 실행:", baseline)
print("if True 실행:", if_true_time)
print("if False 실행:", if_false_time)

# 한 번 실행에 대한 시간 -> (초 단위) -> ns값으로 변환하기 위해 10억을 곱하기
print("if True 추가 비용(ns):", (if_true_time - baseline) / N * 1_000_000_000)
print("if False 추가 비용(ns):", (if_false_time - baseline) / N * 1_000_000_000)

# `if`문을 잘 쓰기 위한 방법들

1. **조건식 비용 관리**: 비싼 조건은 필요할 때에만 실행되도록 뒤쪽에 배치해야 합니다.
2. **단락 평가의 최적화**(`short-circuit`): `and`같이 모두 만족해야 하는 경우, 파이썬은 앞부분만 연산한 뒤 `False`인 경우에는 바로 탈락시키기 때문에 앞부분에 탈락 확률이 높은 변수를 두는 것이 좋습니다.
3. **조건 순서 최적화**: 위와 비슷하게 빠르게 성공시키거나, 계산 비용이 적은 조건을 먼저 나오게 하면 좋습니다.
4. **`if`/`elif`**: 배타적인 조건이면 불필요한 검사 방지를 위해 `elif`/`else`를 사용하면 좋습니다.
5. **내부 연산의 최적화**: 내부 `if` 연산은 `O(1)`에 가까운 것을 사용하는 것이 일반적으로 좋습니다.
6. **딕셔너리 분기처리**: 명령어에 따라 함수를 실행하는 경우에는 **dispatch table(전략 패턴)**을 이용하기 적합합니다.
7. **분기 보호**: 가독성과 유지보수를 위해 `guard clause` 방식을 사용하면 좋습니다. (중첩 `if`문 자제)
8. **`match-case`의 위치와 성능감각**: `match-case`는 성능보다는 구조분해와 패턴 매칭에 읽기 좋게 쓰입니다. 단순 값 비교 시에는 비슷한 성능을 보이고, 복잡한 매칭에서는 무거울 수 있습니다.

import random

def getBool(true_prob: int):
  return random.random() < true_prob / 100

class User:
  def __init__(self, is_login: bool, is_active: bool):
    self.is_login = is_login
    self.is_active = is_active

# f1 = 70% 확률로 False인 객체
f1 = getBool(30)

# t1 = 80% 확률로 True 객체
t1 = getBool(80)

# 위와같은 변수의 경우

# 배타적 조건
# 높은 확률 먼저 계산
def example_low_calc(t1: bool, f1: bool) -> None:
  if f1 and t1:
    print("both True")
  # 배타적 조건으로 elif, True일 확률이 높은 t1 먼저 (t1은 80%, f1은 30%)
  elif t1:
    print("t1 only True")
  elif f1:
    print("f1 only True")
  else:
    print("both not True")
  
  # 아래와 같이도 가능
  match (t1, f1):
    case True, True:
      print("both True")
    case True, _:
      print("t1 only True")
    case _, True:
      print("f1 only True")
    case _:
      print("both not True")

example_low_calc(t1, f1)

# guard clause
def example_guard_clause():  
  # 70% 확률로 존재하는 사용자,
  # 40%확률로 로그인
  # login되어있으면 30%확률로 활성화
  user = User(is_login := getBool(40), is_active=(getBool(30) and is_login)) if getBool(70) else None

  # 잘못된 예시
  if user is not None:
    if user.is_login:
      if user.is_active:
        print("user_active")
        # 너무 depth가 깊어짐


  # 올바른 guard clause의 사용
  if user is None:
    print("no user")
    return
  print("user exist")

  if not user.is_login:
    print("user not login")
    return
  print("user logged in")
  
  if not user.is_active:
    print("user not active")

  print("user active")

# match-case가 비효율적인 경우
def example_inefficient_match():
  # match-case가 오래 걸리는 경우는 단순 값 비교가 아닌 직접 뜯어서 찾아봐야 하는 경우입니다.
  data = {
    "type": "IT",
    "name": "developer",
    "salary": 3000
  }

  # 이전에는 if를 사용하였지만 아래와 같은 경우에는 비효율적입니다.
  
  # 1. dict 타입의 내부 값을 하나씩 확인해야 하는 경우
  match data:
    case {"type": "IT", "name": "frontend", "salary": _}:
      print("IT frontend ?")
    case {"type": "IT", "name": "developer", "salary": 3000}:
      print("IT developer 3000")
  
  # 위와 같은 경우에는 이렇게 직접 조건을 확인해 속도를 더 향상할 수 있습니다.
  if data.get("type") == "IT" and data.get("name") == "frontend" and "salary" in data:
    print("IT frontend ?")
  elif data.get("type") == "IT" and data.get("name") == "developer" and data.get("salary") == 3000:
    print("IT developer 3000")

# Iterable
이터러블은 반복 가능한 객체를 말합니다.
`for`문에 넣어서 하나씩 꺼낼 수 있는 객체입니다.

> `list`, `tuple`, `str`, `dict`, `set`, `range`, `generator` 등이 모두 `iterable`입니다. 시퀀스는 항상 `__iter__()` 메서드를 지원합니다.

이는 `__iter__()` 같은 메서드로 지원됩니다.


# Iterator
이터레이터는 실제로 `next()`로 값을 하나씩 꺼내는 객체입니다.
[파이썬 공식 문서](https://docs.python.org/3.10/library/stdtypes.html)에서 `Ctrl + F` 후 `StopIteration`를 찾아보면 이는 `__next__()`로 작동하며 마지막 값에서 `StopIteration` 예외를 발생시킨다고 나와 있습니다.

# Generator
값을 미리 다 만들지 않고 필요할 때 생성하는 `iterator`입니다.

동일하게 [파이썬 공식 문서](https://docs.python.org/3.10/library/stdtypes.html)에서 `Ctrl + F` 후 `Generator`를 써보면 설명에 자동으로 다음 값을 만들어 반환한다고 나와 있습니다.

예시로는 `(x * 2 for x in range(5))`와 같은 generator expression 등이 있으며 값은 `__next__()`가 호출될 때 지연 평가된다고 합니다.

> 이 때문에 제너레이터는 `match-case`의 시퀀스 패턴에서 일반 시퀀스처럼 매칭되지 않을 수 있습니다.

# Sequence
순서와 위치가 있는 `iterable`입니다.

`set`, `dict` 같은 자료구조도 `iterable` 객체이지만, `sequence`는 확실하게 인덱스와 순서가 존재하는 값입니다.

```
Iterable

│
├─ Mapping
│  └─ dict

├─ Set
│  └─ set

```

# for문과 while문
`for`문과 `while`문은 모두 반복문이지만 (지금보니) 동작하는 구조가 꽤 다르다는 것을 알 수 있습니다.

## `while 조건:`
`while`문은 조건식이 `True`인 동안 반복하게 됩니다.

이때, 실행 구문 과정에서 조건에 대한 결과가 바뀌더라도 끝까지 실행 중인 구문을 완료한 뒤 조건문 체크에서 다시 체크를 하게 됩니다.

예를 들어 아래와 같은 코드는 10번 반복되게 됩니다.
```python
a = 0
i = 0
while a == 0 and i < 10:
  # True면 여기서부터 실행
  a += 1
  print(a)
  a -= 1
  i += 1
  # 여기까지 실행 후 다시 올라가기
# False면 여기로 이동
```

if문의 비용

if문 자체는 if 다음의 연산을 수행하여 결과(boolean)에 따라 다음 코드 수행 위치를 이동시키는 것이 전부입니다.

여기에서 if문 뒤에 수행하는 연산을 제외하면 if문 자체에 대한 오버헤드는 거의 없다고 볼 수 있습니다.

따라서 실제로 신경 써야 하는 부분은 if문이라는 문법 자체보다 조건식 안에서 어떤 연산을 수행하는지입니다.

    "pass",

if_true_time = timeit.timeit(
    """

    pass
""",
    setup="x = True",
    number=N
)

# x = False에 대한 1000만번 실행 시간

    pass
""",
    setup="x = False",

print("if False 추가 비용(ns):", (if_false_time - baseline) / N * 1_000_000_000)

조건식을 잘 배치하는 방법

조건식 비용 관리

비싼 조건은 필요할 때에만 실행되도록 뒤쪽에 배치해야 합니다.

and같이 모두 만족해야 하는 경우, 파이썬은 앞부분만 연산한 뒤 False인 경우에는 바로 탈락시키기 때문에 앞부분에 탈락 확률이 높은 변수를 두는 것이 좋습니다.

조건 순서와 배타 조건

빠르게 성공시키거나, 계산 비용이 적은 조건을 먼저 나오게 하면 좋습니다.

배타적인 조건이면 불필요한 검사 방지를 위해 elif/else를 사용하면 좋습니다.

분기 보호와 딕셔너리 분기처리

가독성과 유지보수를 위해 guard clause 방식을 사용하면 좋습니다.

명령어에 따라 함수를 실행하는 경우에는 dispatch table(전략 패턴)을 이용하기 적합합니다.

match-case의 위치

match-case는 성능보다는 구조분해와 패턴 매칭에 읽기 좋게 쓰입니다.

단순 값 비교 시에는 비슷한 성능을 보이고, 복잡한 매칭에서는 무거울 수 있습니다.

분기 처리 예시

and 단락 평가 예시

getBool(true_prob)은 예시 데이터를 만들기 위한 함수입니다.

핵심은 and 연산에서 앞 조건이 False이면 뒤 조건을 평가하지 않는다는 점입니다. 그래서 실패할 확률이 높은 조건을 앞에 두면 불필요한 연산을 줄일 수 있습니다.

t1 == True처럼 비교하지 않아도, t1 자체가 boolean 값이기 때문에 elif t1:처럼 사용할 수 있습니다.

# 예를 들어 보겠습니다.
import random

def getBool(true_prob: int):
  return random.random() < true_prob / 100

# f1 = 70% 확률로 False인 객체
f1 = getBool(30)

# t1 = 80% 확률로 True 객체
t1 = getBool(80)

# 위와같은 변수의 경우

# 배타적 조건
# 높은 확률 먼저 계산
def example_low_calc(t1: bool, f1: bool) -> None:
  # f1은 True 확률이 30%이므로, and 연산에서 먼저 검사하면 t1 평가를 줄일 수 있습니다.
  if f1 and t1:
    print("both True")
  # 배타적 조건으로 elif, True일 확률이 높은 t1 먼저 (t1은 80%, f1은 30%)
  elif t1:
    print("t1 only True")
  elif f1:
    print("f1 only True")
  else:
    print("both not True")

guard clause

guard clause는 먼저 예외적인 조건을 반환시켜 중첩 if문을 줄이는 방식입니다.

  # 70% 확률로 존재하는 사용자,

  # 잘못된 예시
  if user is not None:
    if user.is_login:
      if user.is_active:
        print("user_active")
        # 너무 depth가 깊어짐

  # 올바른 guard clause의 사용
  if user is None:
    print("no user")
    return
  print("user exist")

  if not user.is_login:
    print("user not login")
    return
  print("user logged in")
  
  if not user.is_active:
    print("user not active")
    return
  print("user active")

Iterable, Iterator, Generator

Iterable

이터러블은 반복 가능한 객체를 말합니다. for문에 넣어서 하나씩 꺼낼 수 있는 객체입니다.

list, tuple, str, dict, set, range, generator 등이 모두 iterable입니다.

Iterator

이터레이터는 실제로 next()로 값을 하나씩 꺼내는 객체입니다.

마지막 값 이후에는 StopIteration 예외를 발생시킵니다.

Generator

제너레이터는 값을 미리 다 만들지 않고 필요할 때 생성하는 iterator입니다.

예시로는 (x * 2 for x in range(5))와 같은 generator expression 등이 있으며 값은 __next__()가 호출될 때 지연 평가된다고 합니다.

제너레이터는 match-case의 시퀀스 패턴에서 일반 시퀀스처럼 매칭되지 않을 수 있습니다.

while문

while문은 조건식이 True인 동안 반복하게 됩니다.

실행 구문 과정에서 조건에 대한 결과가 바뀌더라도 끝까지 실행 중인 구문을 완료한 뒤 조건문 체크에서 다시 체크를 하게 됩니다.

a = 0
i = 0
while a == 0 and i < 10:
  # True면 여기서부터 실행
  a += 1
  print(a)
  a -= 1
  i += 1
  # 여기까지 실행 후 다시 올라가기
# False면 여기로 이동

for문

for문은 내부적으로 iterable에서 값을 하나씩 꺼내는 반복문입니다.

전통적인 for (int i = 0; i < 10; i++) {...} 형태와 다르게, 파이썬의 for문은 값을 하나씩 꺼내는 방식입니다.

it = iter([10, 20, 30, 40, 50])

while True:
  try:
    x = next(it)
    print(x)
  except StopIteration:
    break
