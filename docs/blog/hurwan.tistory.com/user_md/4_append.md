# 첫번째 포스팅에 올리지 못한부분 채우기
## IEEE 754 표준이란 무엇인가? 
IEEE는 전기, 전자, 컴퓨터, 통신 분야의 국제적인 학회/기술 단체로 내부적으로 IEEE-SA라는 Standards Association (표준 협회)가 존재합니다. 여기에서 여러 기술 분야에 대한 표준을 개발합니다.
그중에서 32비트, 64비트 부동소수점은 IEEE 754 표준으로 이는 **실수 계산 전반**을 결정합니다.
- 부동 소수점 저장 형식: `[sign] [exponent] [fraction/mantissa]`
- 32비트 float: 단정도, single precision `[1] [8] [23]`길이의 비트
- 64비트 double: 배정도, double precision `[1] [11] [52]`길이의 비트. (이건 지수부에 1023을 더합니다. 11비트 = 0~2048 = `-1023`~`1025`)
- 반올림 방식: 가장 가까운 값으로 반올림 등
- 특수 값: +∞, -∞, NaN, +0, -0
- 아주 작은 수 처리
- 연산 규칙
등을 처리합니다.

추가적으로 `binary [16 | 32 | 64 | 128]`, `demical [32 | 64 | 128]`(10진법 부동소수점) 등이 존재합니다.
## 부동소수점 오차는 실제 개발에서 어떤 문제를 발생시키는가?
앞에서 작은 계산 값 오류 (하지만 치명적일 수 있음)을 낸다고 하였지만 이외에도
- 비교 오류
- 누적 오차 (점점 오차가 쌓임)
- 무한루프 (실수값이 정확히 목표에 도달하지 못함)
- 데이터 처리 오류 (그룹화, 정렬 기준이 이상해짐)
- AI/과학 계산 오류 (`inf`, `NaN`, 언더플로우, 오버플로우)
등이 존재합니다.

# 금융/게임/AI 분야에서 소수 오차를 어떻게 처리하는가?
실제 금융/게임/AI에서는 `float` 대신에 `Demical` 타입을 사용합니다. 
`Demical`은 **10진수 문자열** 기반으로 수를 표현하여 인자로 `string`를 주어야합니다. (숫자를 주면 오차값을 만들 수 있습니다.)

### `Demical`의 연산 방식
연산을 할 때 결국 `float`와 동일한 문제가 생기지 않을까 했지만 다른 방식으로 돌아가는 것을 확인했습니다.
예를 들어 `Demical("12.90")`은 내부적으로
```
sign = 0
confficient = 1290
exponent = -2
```
와 같이 설정이 되어 `(-1)^sign × coefficient × 10^exponent`와 같은 형태로 해석이 된다고 합니다.

따라서 계산을 할 때에도 `exponent`를 맞추어 더하던가 그냥 곱하던가, `confficient`와 `sign`도 정수 형태로 정상적인 계산이 가능합니다.

### `Demical`을 사용해도 조심해야할 점
`Demical`은 무한소수는 어떻게 처리가 안되기 때문에 어느정도 타협을 하거나 아예 분자&분모 식으로 저장을 하는 것도 방법이 될 수 있을 것 같습니다.

추가로 `Epsilon`이라는 방식을 통해 미세한 차이는 동일하게 간주하는 방식을 채택하기도 한다고 합니다.
