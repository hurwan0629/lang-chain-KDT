# 그래프 자료구조

그래프는 점들과 점 사이의 연결을 표현하는 자료구조입니다.

트리 또한 그래프의 한 종류이고, 그래프가 더 일반적인 구조입니다.

그래프는 정점과 간선으로 이루어져 있습니다.

예를 들어
```
A - B     A - B
| X |     | /
C - D     C - D
```
등과 같이 생길 수 있습니다.

이는 데이터 자체보다 관계를 표현할 대 강한 자료구조이며, 네트워크 등에도 자주 사용됩니다. 다른 예시로는 SNS 친밀도, 도시와의 관계, 노선도 등이 있습니다.

## 그래프의 종류
그래프는 크게 5가지 종류가 존재합니다.
1. 무방향 그래프: 간선에 방향이 없어 서로 상하관계 없이 연결되어있는 형태입니다.
2. 방향 그래프: 간선에 방향이 존재하여 예를 들어 `A → B`의 경우에는 A에서 B로 갈 수 있지만 B에서 A로는 다른 경로 없이는 가지 못하는 상태입니다. 웹 링크, 작업 순서, 팔로우 등과 같은 형태에 쓰입니다.
3. 가중치 그래프: 간선 자체에 비용, 거리, 시간같은 값이 있어 예를 들어 `A -[300]-> B`라는 `A`에서 `B`로 가기 위해 `300`의 비용이 든다 라는 것을 나타내는 방식이 존재합니다.
4. 사이클이 있는 그래프: 하나의 정점에서 나간 간선이 이어져서 다른 방향으로 돌아올 경우, 사이클이 존재한다고 합니다.
5. DAG (Directed Acyclic Graph): 방향이 있지만 사이클은 없는 그래프입니다. 이는 작업 순서, 빌드 순서, 선수 과목, 의존성 관리에 많이 나오게 됩니다.

## 그래프의 저장 방식
그래프는 보통 2가지 방식으로 저장하게 됩니다.
### 인접행렬
정점끼리의 연결 여부를 2차원 배열로 저장합니다.
예를 들면 
```
[1번]     [2번]
A - B     A - B
| X |     | /
C - D     C - D
```
1번의 경우에는
```
  A B C D
A 0 1 1 1 
B 1 0 1 1
C 1 1 0 1
D 1 1 1 0
```
2번의 경우에는
```
  A B C D
A 0 1 1 0 
B 1 0 1 0
C 1 1 0 1
D 0 0 1 0
```
과 같은 형태가 될 수 있습니다.

이를 통해 A와 D가 연결되었나? 를 확인하기 위해 `map[A, D]`를 통해 확인이 가능합니다.

> 해당 방식의 장점은 두 노드의 연결 상태를 `O(1)`의 상태로 확인이 가능하지만 정점이 많으면 메모리를 많이 사용하게 됩니다.

### 인접 리스트
각 정점마다 연결된 정점 목록을 저장합니다. 같은 예시로 

1번의 경우에는
```
A: [B, C, D]
B: [A, C, D]
C: [A, B, D]
D: [A, B, C]
```
이며, 2번의 경우에는
```
A: [B, C]
B: [A, C]
C: [A, B, D]
D: [C]
```
형태가 되게 됩니다. 

> 해당 방식의 장점은 실제로 연결된 것만 저장해서 메모리 효율이 좋지만, 두 노드가 연결되었는지는 하나의 노드의 리스트를 순회해봐야한다는 문제가 있습니다. 

## 알고리즘과의 연계
그래프의 경우에는 여러 알고리즘과 연동이 됩니다.

그래프를 탐색하는 경우에는 DFS, BFS 그리고 Djikstra 알고리즘과 함께 쓰이기도 합니다.

이외에도 Union-Find, Topological Sort, Kruskal, Prim 등이 존재합니다.
