# Blog HTML 작업 지침

이 폴더는 사용자가 직접 작성한 학습 글을 티스토리 업로드용 HTML로 감싸는 작업 공간이다. 이 폴더에서 Codex의 역할은 글쓰기나 보강이 아니라, 사용자가 확정한 원문에 일관된 HTML 구조와 스타일을 적용하는 것이다.

## 핵심 원칙

- 업로드용 HTML에는 사용자가 작성하지 않은 보강 문장을 추가하지 않는다.
- 사용자가 작성한 글의 흐름, 문장, 표현, 순서를 임의로 바꾸지 않는다.
- Codex는 제목, 목차, 섹션, 카드, 노트, 표, 코드블록, 인라인 코드 같은 HTML 태그와 스타일만 적용한다.
- 오탈자, 문법, 기술 오류, 가독성 문제를 발견하면 파일을 고치기 전에 말로 알려준다.
- 사용자가 명시적으로 요청하기 전에는 원문 `.md` 파일을 직접 수정하지 않는다.
- 기존 번호 HTML은 덮어쓰지 않는다. 새 글은 새 번호 HTML로 만들고, 기존 글의 수정본은 `update_*.html`로 만든다.

## 폴더 역할

- `user_md/`: 사용자가 작성한 원본 Markdown을 보관한다.
- `history/`: 티스토리에 붙여 넣을 최종 HTML과 이전 결과물을 보관한다.
- `templates/`: 공통 스타일과 작업 골격을 확인하는 템플릿을 보관한다.
- `templates/style.css`: 공통 디자인 원본이다. 디자인 변경은 이 파일에서 먼저 확인한다.
- `templates/preview.html`: 디자인 확인용 샘플 페이지다. 실제 업로드 글이 아니다.
- `templates/post_template.html`: 새 HTML을 만들 때 사용하는 최소 골격이다.

## 작업 흐름

1. 새 `.md` 또는 `.html` 파일을 받으면 먼저 원문을 읽는다.
2. 글을 어떤 흐름으로 읽을 수 있는지 말로 요약한다.
3. 치명적인 기술 오류, 문법 문제, 렌더링 깨짐, 가독성 문제를 말로 보고한다.
4. 사용자가 수정 방향을 결정하거나 HTML 생성을 요청하면 그 범위 안에서만 작업한다.
5. HTML 생성 시 원문 문장 자체는 그대로 두고, 구조화 태그와 스타일만 입힌다.
6. 작업 후 파일 존재, 목차, 섹션 id, 코드블록, 표, 토글, 닫는 태그를 확인한다.

## 금지 작업

- 원문에 없는 설명, 예시, 정의, 결론을 추가하지 않는다.
- 문장을 더 자연스럽게 보이도록 임의로 재작성하지 않는다.
- 문단 순서를 임의로 바꾸지 않는다.
- 오탈자를 발견해도 사용자 승인 없이 고치지 않는다.
- 기술적으로 틀렸다고 판단한 내용을 사용자 승인 없이 조용히 수정하지 않는다.

## 허용 작업

- Markdown 제목을 HTML 제목/섹션으로 변환한다.
- 목차를 만든다.
- 긴 본문을 `.post-section`, `.post-card.stack`, `.post-note` 같은 구조로 감싼다.
- 표를 `.read-table` 스타일로 변환한다.
- 코드블록과 계산 예시를 `.code-box` 또는 `.output-box`로 감싼다.
- 백틱으로 표시된 짧은 코드 표현을 `<code>`로 변환한다.
- 사용자가 원하면 원본 확인용 `<details class="source-toggle">`를 추가한다.

## 스타일 기준

- 전체 래퍼는 `.tech-post`를 사용한다.
- 기본 톤은 흰 배경, 초록 포인트 컬러(`#19b97c`), 밝은 카드형 레이아웃을 유지한다.
- 글 상단에는 `.post-hero`를 사용하고, `post-kicker`, `post-title`, `post-subtitle` 구조를 둔다.
- 목차는 `.post-toc`으로 만들고, 각 섹션은 `section-01`, `section-02` 같은 id를 가진다.
- 본문 섹션은 `.post-section`, 카드형 설명은 `.post-card.stack`을 사용한다.
- 강조 노트는 `.post-note`를 사용한다.
- 표는 `.read-table`을 사용한다.
- 코드 블록 또는 계산 예시는 `.output-box` 또는 `.code-box`를 사용한다.
- 일반 본문 문단은 `font-weight: 500`, `color: #334155` 기준을 유지한다.

## 인라인 코드 처리

- 본문 중 `a = "hello"`, `.py`, `co_code`, `int`, `float`, `globals()` 같은 짧은 코드/기호 표현은 `<code>`로 감싼다.
- 인라인 `<code>`는 밝은 회색 배경(`#f1f5f9`)과 작은 border를 적용한다.
- 코드 블록의 `<pre><code>...</code></pre>`에는 인라인 코드 스타일이 덮어씌워지지 않게 한다.
- 마크다운 백틱이 HTML 본문에 그대로 남지 않도록 필요한 경우 `<code>`로 바꾼다.

## 원본 토글

- 사용자가 원문 확인을 원하면 글 상단, hero 아래에 `<details class="source-toggle">`를 추가한다.
- 첫 번째 원본 토글 제목은 사용자가 별도 지정하지 않으면 `gpt가 디자인 하기 전 원본`을 사용한다.
- 토글 안에는 원문을 최대한 그대로 보존한다.
- 토글 내부의 원문은 `<pre class="source-box"><code>...</code></pre>` 형태로 넣는다.
- HTML에서 깨질 수 있는 `&`, `<`, `>`, `->` 등은 표시가 유지되도록 이스케이프한다.

## 내용 검토 기준

HTML 생성 전 다음을 확인한다.

- 마크다운 코드블록 ```가 열리고 닫혔는지 확인한다.
- 표가 코드블록 안에 들어가 있으면 일반 표 렌더링이 필요한지 확인한다.
- 기술 오류가 있으면 사용자에게 조언한다.
- 확실하지 않은 기술 사실은 단정하지 말고 재확인이 필요하다고 말한다.
- 오탈자는 발견해도 사용자가 요청하지 않으면 원문을 고치지 않는다.

## 파일 생성 규칙

- 기존 번호 HTML을 직접 덮어쓰지 않는다.
- 기존 글 개선본은 `update_1.html`, `update_2.html`처럼 만든다.
- 새 글은 다음 번호의 HTML 파일로 만든다.
- 디자인 확인은 `templates/preview.html`에서 한다.
- 최종 업로드 HTML은 단일 파일이어야 하므로 `templates/style.css` 내용을 `<style>` 태그로 인라인 삽입한다.
- 공통 골격은 `templates/post_template.html`을 우선 참고한다.
- 생성 후에는 `Get-ChildItem`과 `Select-String` 등으로 파일 존재, 토글, 목차, 섹션, 닫는 태그를 확인한다.
