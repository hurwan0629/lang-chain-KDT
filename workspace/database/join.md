# 데이터베이스 물리 JOIN의 종류
데이터베이스에는 `INNER`, `OUTER`, `CROSS` 외에도 물리적인, 실제로 조건에 맞는 행을 어떤 방식으로 고를지에 대한 실행 계획의 `JOIN`이 존재합니다.

먼저 나열하고 시작하면 이번 글에서는 아래의 개념에 대해 다룹니다.
- `NESTED LOOP JOIN`
- `INDEX NESTED LOOP JOIN`
- `BLOCK NESTED LOOP JOIN`
- `HASH JOIN`
- `SORT MERGE JOIN`

## NESTED LOOP JOIN
가장 단순한 방식으로 만약 `A_TABLE.id` 와 `B_TABLE.a_id`를 통해 `JOIN`을 실행할 시, 인덱스 없이 `A_TABLE`의 모든 행의 개수에 `B_TABLE`의 모든 행의 개수를 곱한만큼 루프를 돌리는 방식입니다. 각각 1,000개의 행이 존재한다 하면 총 1,000,000번 순회한다고 볼 수 있습니다.

작은 테이블과 큰 테이블을 조인할 때는 나쁘지 않을 수 있지만 규모가 커질수록 성능이 좋아질 수 없는 방식입니다.

## INDEX NESTED LOOP JOIN
`FROM A JOIN B ON a.id = b.a_id`를 할 때 안쪽 테이블을 보통 `b`라고 가정합니다. 여기에서 바깥쪽 테이블(`A`)를 모두 순회하며 안쪽 테이블(`B`)에서 인덱스를 통해 바깥쪽 테이블과 맞는 행을 빠르게 찾는 방식입니다. 의사 코드로 표현하면 다음과 같습니다.
```python 
result = []
for a_id in A:
  result += B[B["a_id"].joinable_with(a_id)]
```

> 보통 실무에서 흔하게 사용되며 PK, FK, WHERE, JOIN 조건에 인덱스가 있으면 자주 쓰이게 됩니다.

## BLOCKED NESTED LOOP JOIN
위에서 `NESTED LOOP`는 모두 순회하였을 때 안쪽 테이블을 굉장히 많이 순회하기 때문에 (N중 반복문 순회 수만큼) 바깥 테이블의 여러 행을 메모리 버퍼에 담아서 안쪽 테이블과 비교할 수 있습니다. 이를 통해서 안쪽 테이블의 탐색 횟수를 버퍼의 크기와 비례하게 줄일 수 있습니다.

## HASH JOIN
JOIN 조건 컬럼을 기준으로 해시 테이블을 만들어서 찾는 방식입니다.

예를 들어서 `FROM A JOIN B ON A.id = B.a_id`에서 `A`가 더 작은 테이블이라 판단할 시 `A` 테이블을 `{ A.id: A.find_by_id[id] }`와 같이 키와 행을 한쌍으로 갖는 해시테이블을 생성합니다. 이후 `B`를 읽어가면서 `A 해시테이블`의 키값을 넣어주면서 결과를 생성해 나가는 방식입니다.

이 방식은 `EQUAL JOIN`만 가능하기 때문에 범위 탐색에서 처리할 수 없습니다. 예를 들어 `ON A.id > B.a_id`같은 조건입니다.

## SORT MERGE JOIN
두 `JOIN 컬럼`을 기준으로 정렬하여 앞에서부터 두 포인터가 작은 것부터 앞으로 오며 매칭해 나가는 방식입니다.

이 방식은 `정렬 비용이 든다`는 특징이 존재하지만 범위 비교가 가능하기 때문에 정렬되어있는 테이블들의 범위 JOIN에 유용하게 쓰일 수 있습니다.
