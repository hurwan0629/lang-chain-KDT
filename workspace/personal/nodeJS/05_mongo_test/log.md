# 몽고와 아틀라스, 그리고 Node를 통한 연결
이번에는 `MongoDB`를 새로 쓰게 되었습니다. 이전까지는 `RDB`만을 사용하였었는데 최근에 말로 많이 듣던 `NoSQL`의 대표격인 `MongoDB`를 수업에서 들었습니다.

## 몽고에 대해서
`Mongo`는 `NoSQL`답게 `JSON`형태와 유사한 `BSON` 자료구조를 통해 데이터를 저장합니다.

몽고는 SQL처럼 테이블/행/컬럼 과 같이 데이터를 다루지 않으며 **컬렉션**을 통해 데이터를 다룹니다. 또한 `_id: ObjectId("12바이트")`를 통해 데이터를 식별하기 위한 키를 자동으로 붙여줍니다.

### 문법
0. `db.use("사용할 데이터베이스)`, `db.컬렉션.메서드()`
1. `.insertOne({})`: 삽입
2. `.insertMany([{}...])`: 다중 삽입
3. `.find({조건}, {선택할 속성들})`: 조회
  - 중첩 객체는 `find("person.age": 20)` 와 같이 접근 가능합니다.
  - > 조건
    - `{age: 0, name: "hurwan"}`: age가 0이고 `name`가 `hurwan"`인 객체 전체
    - `{age: { $eq: 20 }}`: `age`가 20과 같은 객체들
    - `{age: { $gt: 20 }}`: `age`가 20 초과인 객체들
    - `{age: { $gte: 20 }}`: `age`가 20 이상인 객체들
    - `{age: { $lt: 20 }}`: `age`가 20 미만인 객체들
    - `{age: { $lte: 20 }}`: `age`가 20 이하인 객체들
    - `{age: { $in: [20, 21, 22] }}`: `age`가 `[20, 21, 22]` 중 하나인 객체들
    - `{age: { $nin: [20, 21, 22] }}`: `age`가 `[20, 21, 22]`가 아닌 객체들
    - 위 조건들은 `,` 를 통해 `and` 와 같이 사용 가능합니다.
  - > 정렬
    - `.sort({ 속성: 1 또는 -1 })`
  - > 제한 및 스킵
    - `.skip(건너뛸 개수)`
    - `.limit(뽑을 개수)`

4. `.updateOne({수정할 객체 조건}, { $set: { 수정 내용 } })`: 객체 하나 수정. (가장 먼저 탐색된 객체)
5. `.updateMany({찾을 객체 조건}, { $set: { 수정 내용 } })`: 객체 모두 수정
  - `$set`: 값 설정 / 필드 추가 
  - `$unset`: 필드 삭제        
  - `$inc`: 숫자 증가/감소     
  - `$push`: 배열에 추가       
  - `$pull`: 배열에서 제거      
  - `$addToSet`: 중복 없이 배열에 추가 
6. `.deleteOne({조건})`: 데이터 삭제
7. `.deleteMany({조건})`: 데이터 여러개 삭제

이외에도 집계(파이프라인방식), join 등도 가능합니다.

### 속도
몽고DB는 `key-value` 형태의 문서로 그대로 저장하는 방식이기 때문에 같이 쓰는 데이터를 한 문서 안에 넣는 구조에 강합니다.

`BSON`은 `JSON`처럼 파일 하나를 디스크에 쭉 저장하는 느김보다는 DB 엔진이 문서 데이터 자체 저장 포맷으로 페이지/블록 단위로 관리하며 별도의 인덱스 구조를 같이 유지하는 형태가 됩니다.

또한 한 컬렉션에서 인덱싱을 담당하는 속성들은 따로 파일이 생성되어 관리되게 되는 형태입니다.

`JOIN`은 `$lookup`을 통해 할 수 있는데 
```javascript
db.orders.aggregate([
  {
    $lookup: {
      from: "users",
      localField: "userId",
      foreignField: "_id",
      as: "user"
    }
  }
])
```
와 같이 작성하게 된다면
```javascript
{
  _id: ObjectId("order1"),
  userId: ObjectId("user1"),
  product: "keyboard",
  user: [
    {
      _id: ObjectId("user1"),
      name: "kim",
      email: "kim@test.com"
    }
  ]
}
```
와 같이 결과가 나오게 됩니다.

순서는 대략적으로
`orders` 문서 읽기 -> `order.userId`확인 -> `users`문서에서 `order.user` 배열에 붙이기 방식으로 이루어집니다.

이는 인덱싱과 `nested loop join`, `merge join`등과 같은 실행 계속을 세우는 RDB들과는 다른 방식을 보여주게 됩니다.

방식 자체를 더 효율화할 수 있지만 기본 철학 자체가 자주 같이 읽는 데이터를 한 문서에 두는 것에 있습니다.

## ATLAS와 연결
`ATLAS`는 기본적으로 몽고에서 제공하는 클라우드 몽고 데이터베이스 서비스입니다.

여기에는 3개의 서버 (주서버1개, 보조서버 2개)가 기본으로 클러스팅되어 사용이 가능합니다.

이때 드라이브를 통한 연결 방식은 2가지가 존재하는데 `mongodb://` 방식과 `mongodb+srv://` 방식입니다.

`Node`, `VSCode` 등을 통해서 연결하는 경우에는 `+srv` 방식을 사용할 시 사용하는 DNS가 `SRV`, `TXT` 레코드를 지원하지 않으면 연결이 실패할 수 있기 때문에 우선 구글 DNS (`8.8.8.8`, `1.1.1.1`)을 사용해본 뒤 안될 시 최종적으로 `mongodb`를 사용하는 것을 권장합니다.
