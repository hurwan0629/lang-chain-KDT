# 노드 JS
노드 JS는 자바 스크립트를 브라우저 외의 터미널 및 서버에서 실행 가능하게 해주는 프로그램입니다.

### 노드의 특징
- 비동기 기능이 효율적이고 쉽게 잘 구현되어있음 (이벤트 루프)
- 싱글 스레드
- 높은 처리 성능
- 

### 패키지
노드는 npm을 통해 패키지를 관리하고 프로세스 환경에 저장하는 것이 아닌 `node_modules/`와 `package-lock.json`을 통해 파일로써 관리합니다.

`npm init -y`를 통해 `paskage.json`을 만들어 프로젝트를 생성 및 관리할 수 있습니다.

### CommonJS와 ES6
`ES6`는 자바 스크립트 문법 표준중 하나이며, `CommonJS`는 `Node.js`에서 오래 쓰던 모듈 시스템입니다.

`ES6`는 **ECMAScript 2015**라고 불리는 JavaScript 표준 버전입니다. 이전에는 여러 문법으로 통일되지 않은 문법들이 통합된 버전이라고 볼 수 있습니다. 이를 통해 다음과 같은 문법들이 들어왔습니다.
- `let`
- `const`
- `화살표 함수`
- `class`
- `Promise`
- `template literal` (백틱 표현식)
- `destructuring` (구조 분해 할당)
- `import / export`

`CommonJS`는 `Node.js`에서 오래전부터 사용하던 모듈 불러오기 방식입니다. `Node.js` 초창기에는 브라우저처럼 `<script>`를 통해 JS 파일을 붙이지 않고 서버 코드에서 파일을 나누고 불러오는 방식을 사용했었습니다.

### 모듈
모듈은 파일들을 기능 및 역할별로 나누어 관리하는 방식입니다. 하나의 파일에서 `export`를 하면 다른 파일 또는 디렉터리, 프로젝트에서 `import` 등과 같은 문법을 통해 해당 기능을 가져와 사용할 수 있게 해줍니다.

여기에서 `CommonJS`와 `ES Module`의 모듈 사용 문법은 차이가 존재하는데

##### CommonJS
- `module.exports = {[export할 객체], ...}`
- `require("[불러올 파일 위치 또는 이름]")`

> `CommonJS`는 실행 중에 불러오는 방식으로 반드시 파일 상단에서 사용할 필요가 없습니다. 또한 `require()`는 기본적으로 동기적으로 모듈을 불러옵니다.
> `CommonJS`는 특별한 설정이 없어도 기본값으로 사용되는 모듈 방식입니다. 명시적으로 설정하려면 `.cjs` 확장자를 사용하면 됩니다.
##### ES Module
`ES Module`은 `ES6`에서 공식적으로 추가된 표준 모듈 시스템입니다.
- `export`: 한 파일에서 여러 대상에 대해 사용이 가능하며 이름을 그대로 사용해야합니다.
- `export default`: 한 파일에서 대표적인 단 하나의 값만 내보낼 수 있으며 외부에서 사용 시 이름을 자유롭게 조작 가능합니다.
- `import [(export default한거) | { export 한것들, ... }] from 경로`

> `ES Module`는 반드시 파일 최상단에 배치시켜주어야 합니다. 브라우저 환경까지 고려하여 만들어져 더 구조적으로 더 정적이고 비동기 로딩과 잘 맞습니다. 
> `ES Module`를 사용하기 위해서는 `package.json`의 `"type": "module"` 설정하거나 파일 확장자를 `.mjs`로 사용할 필요가 있습니다.

### express.js
`Express`는 `Node.js`에서 백엔드 서버를 만들 때 가장 자주 사용되는 프레임워크입니다. 파이썬의 `Fast API`와 같이 간편하고 빠르게 서버를 만들 수 있습니다.

> `Node.js`는 기본 모듈 `http`만을 통해서도 서버를 만들 수 있지만 코드가 지저분해지기 쉽습니다.

사용 순서는
1. 콘솔에 `npm install express`
2. 콘솔에 `npm init -y`를 작성합니다. (필수는 아니지만 강한 권장)
3. 코드에 `express` 모듈 받아오기
4. 받아온 모듈을 실행(`express()`)하여 어플리케이션 객체를 생성하여줍니다.



### 환경 변수
`Node.js`의 환경 변수는 아래와 같이 사용 가능합니다.
- `provess.env.[환경변수 명]`

또한 실행 폴더에 `.env` 파일을 만들어 `dotenv` 패키지를 통해 모듈의 `.config()`를 통해 `.env`파일을 읽어오는 것이 가능합니다.

`NODE_ENV`라는 환경 설정을 나타내는 환경 변수가 있습니다.

예를 들어 `NODE_ENV=development`라면 개발환경이라는 뜻, `NODE_ENV=test`라면 테스트 환경이라는 의미가 되어 분기를 나눠주는 역할을 할 수도 있습니다.
