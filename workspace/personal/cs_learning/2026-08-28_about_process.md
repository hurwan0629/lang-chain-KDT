# [Computer Science] 프로세스의 개념과 관리

## 프로그램과 프로세스
디스크에는 `main.py`, `server.js`와 같은 파일이 있으며 리눅스의 구조로 치면 `/usr/bin/python`과 같은 실행 파일 또한 존재합니다. 

반면 프로세스는 OS가 프로그램을 실행하기 위해 만든 **실행 단위**입니다.

이는 디스크에서 `user/bin/python` 파일을 불러와 실행하여 커널에서 파이썬 프로세스 안에 실행할 코드를 넣고 돌리게 됩니다.

이 때문에 같은 프로그램이여도 여러 프로세스에 존재할 수 있습니다. 예를 들어서 프로세스가 A, B, C가 있으면 이 세개의 프로세스 안에 실행하는 프로그램으로 `user/bin/python`이 존재할 수 있습니다.

커널이 관리하는 프로세스 객체에는 PID라는 프로세스 고유 식별자 정수가 존재합니다.

대략적으로 프로세스 내부에는 다음과 같은 정보가 존재합니다. (임시로 설정한 변수명입니다.)
- PID
- state: 현재 상태 (BLOCKED, SLEEP 등)
- scheduling_info: CPU 스케줄링 정보
- signal: 시그널 정보
- memory_info: 메모리 정보
- relation: 부모/자식 관계
- fd_table: 파일 디스크립터 접근 테이블

> 이렇게 운영체제라고 특별하거나 새로운 구조가 있는것이 아닌 기본적인 개념을 가지며 구조체 및 참조를 이용하여 많은 요소를 관리합니다. (객체지향 관점에서)

## 프로세스의 메모리
모든 프로세스는 자신의 메모리를 가지게 됩니다.

해당 메모리는 유명한 형태로 떨어져있는 페이지들을 순서대로 합쳐놓았을 때 다음과 같은 형태가 됩니다.

```
높은 주소
┌────────────────────┐
│ Stack              │
│                    │
│ ↓                  │
├────────────────────┤
│                    │
│ ↑                  │
│ Heap               │
├────────────────────┤
│ Data / BSS         │
├────────────────────┤
│ Code / Text        │
└────────────────────┘
낮은 주소
```

여기에서 스택은 `for`, `if`, `func()` 등과 같이 지역적인 내용들이 쌓이는 형태이며 `Heap`는 C의 `malloc`과 같은 명령어를 통해 할당하는 메모리를 뜻합니다.

아래에 있는 `Code`, `Text`는 실행할 때 변하지 않는 내용을 말하며 `Data`는 전역변수, `BSS`는 `Block Start by Symbol`이라는 의미로 `0`으로 초기화된 전역변수를 의미합니다.

## CPU가 프로세스를 실행하는 방식
CPU는 프로세스라는 추상 개념을 직접 실행하지 않습니다.

컴퓨터는 몇가지 연산 유닛과 CPU 등의 관점에서 보면 보이지 않는 영역을 굉장히 많은 알고리즘과 자료구조를 이용하여 관리하게 됩니다.

CPU 입장에서 보면 CPU는 `XOR`, `AND`, `OR` 등을 기반으로 한 수십가지에 불과한 회로만을 이용하여 현재 이 글을 보여주고있는 블로그, 자료 등을 나타내는 문자인코딩, 파일, 네트워크 등을 모두 구현하고 있는 것입니다.

CPU에 존재하는 내용은 많으면서도 굉장히 적습니다.
- Register
- PC (Program Counter)
- SP (Stack Pointer)
- 현제 명령어
- 연산용 저장
- ALU

등과 같은 내용이 전부입니다.

보통 인텔의 `x86-64` 아키텍처에서는 보통 다음과 같은 포인터를 사용하게 됩니다.
- RAX (Register A Extended): 누산기 및 리턴값
- RBX (Register B Extended): 포인터 또는 임시 데이터를 저장하는 범용 레지스터
- RSP (Register Stack Pointer): 현재 이후 돌아갈 지점
- RIP (Register Instruction Pointer): 다음 실행 명령어

이를 이용하여 여러 프로세스를 스케줄링하여 돌아가며 작업해주고, 실행하던 지점을 불러와 명령어를 실행 후 시간 또는 조건이 되면 포인터를 저장하고 다음 프로세스를 불러오게 됩니다.

## PID
커널에는 컴퓨터에서 시각적으로 보이는 프로세스 (크롬, VSCODE, 파일 탐색기) 외에도 수십, 수백개의 프로세스가 존재하게 됩니다.

이를 구분하기 위해서 PID를 사용하게 되며 node에서는 process전역 객체에 pid가 저장되어있게 됩니다. (파이썬에서는 `os.getpid()`각 pid를 반환합니다.)

## 프로세스에 존재하는 FD
보통 프로세스가 I/O 작업을 요청하기 위해서 커널의 파일 객체에 fd(`file descripter`)를 이용하여 접근하게 됩니다. 예를 들어 하나의 프로세스 객체(커널이 관리하는) 안에는 위에서 설명하였던 `fd_table`객체가 존재하며 이를 이용하여 프로그램 코드는 커널에 `read(fd, buf, count)`와 같은 호출을 하게됩니다.

커널은 이 호출을 받으면 프로세스의 `program_A.fd_table.fd`와 같은 형태의 위치에 있는 파일에 접근하게 됩니다. 이를 이용해서 프로세스에서 다른 범위에 존재하는 내용을 수정할 수 있으며(권한을 받을 시), 프로세스간 통신, 네트워크 소켓을 다루기 등을 할 수 있습니다.

## 커널이 프로세스의 주소를 관리하는 법
여기서부터는 약간 흐름이 달라집니다.

메모리에는 실제 물리적인 위치와 가상 주소 (보통 프로세스.가상주소 -> 물리 주소)로 나타내어질 수 있습니다.

일반적으로 C 또는 파이썬에서 `id` 또는 위치를 찍게되면 `0x0000...`, `0xFFF..` 등과 같이 출력하게 됩니다. 이는 메모리의 물리 주소가 아닌 해당 주소를 찍은 프로세스에 대한 **논리 주소**를 16진수로 나타낸 것입니다.

보통 물리주소에 대한 단위를 **프레임**이라고 부르며 가상 주소에 대한 단위를 **페이지**라고 부르게 됩니다.

## MMU - Memory Management Unit
MMU는 CPU가 가상 주수 `0x???`에 접근할 때 사용되는 연산기 및 회로입니다.

해당 유닛은 `Page Table`에 접근하여 이를 물리주소로 값을 변환하게 됩니다.

이때 프로세스 객체에는 각각 다른 `page_table` 참조를 가지고 있습니다.

일반적으로 페이지는 4KB 단위로 나뉘어서 사용되게 됩니다. (프레임도 보통 4KB입니다.)

그리고 `page_table[index]`와 같은 형태를 통해 매핑되어있는 물리주소를 가져오게 됩니다. 이때 하나의 프로세스에 종속되어있는 여러 페이지들은 순서대로 연결되어있지 않고 따로따로 동적으로 위치하기 때문에 쉽게 생각나는 `프로세스 주소 + 가상 주소` 형태는 성립하지 않을 수 있습니다.

커널은 보통 이 정보를 프로세스 객체 안의 메모리 구조 객체를 이용하여 관리하며 해당 메모리 구조 객체(구조체)에는 다음과 같은 요소가 존재합니다.

```c
struct mm_struct {
  page_table;
  code_area;
  data_area;
  heap_area;
  stack_area;
  ...
}
```
## Shared Memory
위와 같이 기본적으로 하나의 프로세스는 서로 다른 프로세스의 메모리에 접근이 불가능하지만 경우에 따라 두 프로세스, `Process_A.page[30]`, `Process_B[44]`의 물리 주소를 같은 물리 RAM 위치로 돌릴 수 있습니다.

이를 Shared Memory라고 하며 해당 방식을 사용할 경우에는 동시성 문제가 있기 때문에 `Mutex`, `Semaphore`, `Lock` 등의 기법을 사용해야합니다.
