# DHCP와 DNS
DHCP와 DNS에서 DHCP는 네트워크에서 하위 네트워크 노드에게 네트워크 자원을 자동으로 설정해주는 것과 DNS는 숫자로 분류되는 주소를 문자로써 관리할 수 있게 도와주는 기능입니다. 

## DHCP
DHCP는 `Dynamic Host Configuration Protocol`입니다. 이는 IP의 주소 뿐만 아니라 게이트웨이, DNS 서버 등과 같이 네트워크에 필요한 정보들을 자동으로 할당해주는 프로토콜입니다. 이전 수동 IP 할당 방식에서는 항상 사람이 직접 IP주소, 서브넷 마스크, 기본 게이트웨이(기본으로 데이터가 흐르는 주소), DNS 서버 등을 알려줘야 했었습니다. 하지만 이 방식은 실수가 생기기 쉽고 불편한 방식이였습니다. 이에 따라 DHCP가 주소를 자동으로 제공하게 되었습니다.

일반적으로 집에서는 공유기가 DHCP의 역할을 해서 와이파이 또는 랜선에 접속할 시 즉시, 임대 시간과 함께 네트워크에 필요한 정보들을 제공해줍니다. 

DHCP는 일반적으로 `DORA`라는 흐름을 통해 설명할 수 있습니다.
- `D`: Discover로 클라이언트가 DHCP 서버를 찾으며 IP를 요청하는 방식입니다.
- `O`: Offer로 DHCP 서버가 특정 주소와 함께 주소를 제공하는 방식입니다.
- `R`: Request로 클라이언트가 자기가 받은 주소를 잘 받은게 맞는지, 올바른 서버가 맞는지 확인차 메시지를 보냅니다.
- `A`: Acknoledge로 DHCP서버가 최종적으로 알아차렸다는 의미를 보내줍니다. 이후에는 클라이언트가 해당 주소를 사용합니다.

## DNS
일반적으로 알듯이 IP주소는 사람이 직접 항상 외우기 어려우며 주소가 변할 수 있기 때문에 이를 도메인 네임이라는 형태로 관리하게 됩니다.

일반적으로 주소는 다음과 같은 형태를 띄게 됩니다. `프로토콜://서브도메인.도메인.주소관리자(국가 또는 기관)?쿼리`의 형태를 가지게 됩니다. 

DNS는 하나의 서버로 이루어지지 않고 계층적인 구조를 가집니다.
순서로 보면 
0. 통신사, 공유기, 구글 DNS 등에 질의를 하게 됩니다.
1. Root DNS: 국가/기관 등이 관리하는 도메인 서버의 ip 주소를 주소의 마지막 부분(`.com` 또는 `.kr` 과 같은)을 보고 응답하게 됩니다. 이때 ip주소는 `key-value` 형태로 구성되어있는 데이터를 통해 다음 서버의 ip주소를 알 수 있습니다.
2. TLD DNS: 동일한 과정을 반복하여 `도메인.주소 관리자`(예를 들면 `example.com`)의 주소를 알아내어 알려주게 됩니다.
3. Authoritative DNS: 최종적으로 사용자가 가려는 목적지(`www.example.com`과 같은)를 알려주게 됩니다.

이를 통해 최종적으로 사용자가 입력한 문자열 url을 통해 ip 주소를 알 수 있게 됩니다.

> 일반적으로 사용자가 문자열을 입력할 때마다 이런 과정을 반복하지는 않고, 공유기, 통신사, Google DNS가 이런 작업을 대신 찾아주게 됩니다. 이를 재귀 DNS 서버라고 부르며 응답을 받고 다시 물어보고 하는 것을 최종 목적지를 찾을 때까지 반복하게 됩니다.

# TLS/SSL
TLS와 SSL은 모두 네트워크 통신을 암호화해서 중간에서 데이터를 탈취하거나 조작하지 못하게 하는 보안 계층을 말합니다.

일반적으로 SSL은 이전부터 사용하던 보안 프로토콜의 명칭이며 TLS은 SSL의 후속 표준으로 현재 사용되는 방식을 말합니다.

SSL의 3버전 부터 보안상의 문제에 의해 폐기되엇으며 현재는 TLS 1.2/1.3을 사용하고 있습니다. (SSL 인증서라고 말하는 것도 보통 TLS인 경우가 많습니다.)

## TLS의 필요성
HTTP는 기본적으로 평문 통신입니다. 이 때문에 중간 네트워크에서 누군가가 패킷을 보면 내용이 그대로 보이게 되는데 TLS는 이를 막기위해 사용하게 됩니다.

TLS는 3가지 기능을 담당해줍니다.
1. 기밀성: 탈취당해도 못보게함 (암호화)
2. 무결성: 데이터가 바뀌면 탐지 가능하게 함
3. 인증: 통신하고 있는 서버가 내가 접속한 서버가 맞는지

HTTPS는 HTTP에 TLS를 합친 것으로 `HTTP over TLS` 라고 불리게 됩니다.

## TLS의 과정
TLS는 브라우저가 서버에 HTTP 요청을 보낼 때 TLS를 통해 암호화를 먼저 한 뒤 TCP를 통해 전송하게 됩니다.

TLS는 크게 두단계로 볼 수 있습니다.
1. Handshake: 서로 누구인지 확인
2. Application Data: 정해진 키로 실제 데이터를 암호화해서 주고받기

이를 전체적으로 풀어보면
1. `ClientHello`: 지원하는 TLS 버전과 지원하는 암호 방식 + 랜덤값을 보내게 됩니다.
2. `ServerHello`: 선택딘 TLS버전과 암호 방식을 통해 서버 인증서를 보내주게 됩니다.
3. 클라이언트의 서버 인증서 검증을 통해 진짜 서버인지 확인하게 됩니다.
4. 서로 같은 세션키를 생성하여 교환합니다.
5. 암호화 통신을 시작하여 HTTP 요청/응답을 암호화해서 주고받게 됩니다.

### 인증서의 형태
인증서 안에는 아래와 같은 정보가 존재합니다.
- 도메인 이름
- 서버 공개 키
- 인증서 발급자
- 유효 기간
- 전자서명

이렇게 받은 서버의 인증서를 브라우저가 확인하게 되는데 다음과 같은 검토를 하게 됩니다.
- 신뢰할 수 있는 CS(Certificate Authority / 인증기관)가 발급한 것인지
- 인증서의 도메인이 내가 접속한 도메인이 맞는지
- 유효 기간이 지난건 아닌지
- 인증서의 위변조 유무

### 대칭키와 공개키, 그리고 CA
**대칭키**는 암호화할때와 복호화 할때 쓰는 키가 같은 방식을 말합니다.

예를 들어서 A와 B가 같은 키를 가지고 있다고 할 경우 이를 대칭키 방식이라고 하며 클라이언트가 데이터를 보낼 때에도 한 키 파일로 암호화를 한 뒤 서버가 복호화를 할 때에도 동일한 키 파일로 하는 방식을 말합니다.

이 방식의 장점은 빠르고 대용량 데이터 암호화에 적합하다는 것이지만 반대로 해당 키를 동기화하기 위해선 이를 한번은 노출시키게 되기 때문에 위험이 존재하는 방식입니다.

**공개키**는 대칭키의 약점을 보완하기 위해 사용하는 방식으로 하나의 공개키(`public key`)와 하나의 개인키(`private key`)를 통해 사용하는 방식을 말합니다.

여기에서 `public key`는 서버 밖에 공개할 수 있는 키이며 `private key`는 절대 서버 밖으로 나가지 않는 키입니다.

서버가 공개키와 개인키 쌍을 가지고 있는 경우, 클라이언트가 서버 공개키를 이용하여 어떤 값을 암호화하면 해당 암호문은 서버의 `private key`를 통해서만 풀 수 있는 방식입니다.

> 간단히 말해서 `public key`는 암호화는 가능하지만 복호화는 불가능한 키입니다.

**공개키의 다른 쓰임**은 **서명**입니디ㅏ. 서명의 경우에는 반대로 개인키를 통해 서명을 한 뒤 공개키를 통해 검증하는 방식입니다.

서버가 특정 데이터를 개인키로 서명을 하는 경우, 클라이언트는 서버 공개키를 통해 확인할 수 있습니다.

이는 데이터의 암호화보다는 무결성 유지에 초점을 둔 방식입니다.

``인증서란 해당 `public key`가 진짜 해당 도메인의 것이다`` 라는 것을 **CA**가 보증해주는 문서를 말합니다.

이는 순서상
1. 서버가 `public/private key`를 생성합니다.
2. 서버가 CA에게 해당 키를 통해 인증서를 발급해달라는 요청을 하여 `도메인`, `공개키`, `발급자`, `유효기간`, `CA의 전자서명`이 담긴 인증서를 발급하게 됩니다.
3. 클라이언트는 브라우저나 OS에 이미 신뢰하는 CA 목록을 기반으로 해당 인증서가 보증된 것인지를 확인하여 서버를 신뢰하게 됩니다.

최종적으로 다음과 같은 형태로 정리할 수 있습니다.
```
서버가 가진 것:
- 인증서
- 공개키
- 개인키

클라이언트가 처음에 받는 것:
- 서버 인증서
- 서버 공개키

클라이언트가 확인하는 것:
- 이 공개키가 진짜 해당 도메인의 공개키인지

양쪽이 최종적으로 만드는 것:
- 같은 세션키

실제 통신에 쓰는 것:
- 세션키
```

## SSH
SSH는 네트워크를 통해 다른 컴퓨터의 셸에 접속할 때, 인증과 암호화를 제공하는 **원격 접속 프로토콜**을 말합니다. (일반적으로 TCP 22번 포트를 사용합니다.)
