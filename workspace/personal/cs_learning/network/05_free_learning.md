## 시스템 콜
일반적으로 일반적으로 운영체제에서 제공하는 사용자 프로그램의 4계층 이하의 작업을 대신 처리해주기 위한 요청 명령어라고 할 수 있습니다. 이는 컴퓨터이 보안과 무결성을 지키기 위해 만들어진 기능입니다.

### 사용자 프로그램이 돌아가는 형식
사용자 프로그램은 기본적으로 유저 모드에서 실행되게 됩니다. 유저 모드 프로그램은 다음과 같은 작업을 할 수 없습니다.
- 파일 입출력
- 네트워크 통신
- 메모리 할당
- I/O 장치 접근
- 포트 열기
- 다른 프로세스 제어

위와 같은 작업은 시스템 전체제 영향을 줄 수 있기 때문에 **커널 모드**에서만 가능합니다. 

예를 들어 파이썬에서는 `f = open("파일", "권한")` 을 통해 파일 디스크립터를 할당받게 됩니다. (`open()`의 반환값은 파일 객체입니다.)

이러한 파일 입출력에 대한 권한 요청이 아니여도 Node Express의 `app.listen(3000)`같은 명령어 또한 `Node`의 HTTP 서버를 통해 os 네트워크 API의 `socket()`, `bind()`, `listen()`과 같은 명령어를 통해 네트워크 소켓을 특정 포트와 연결하여 프로그램과 연결해주는 방식을 사용할 수 있습니다.

여기에서 소켓은 커널의 메모리에 존재하는 `포트`, `주소체계`, `TCP 연결 상태`, `버퍼` 등과 같은 정보를 가진 객체일 뿐입니다. 여기에서 포트포워딩이 되어있다면 외부에서 소켓으로 연결된 포트로 데이터가 들어오게되면 커널쪽에서 이를 해설하여 소켓에 연결된 버퍼에 넣어 프로그램이 스트림을 통해 읽을 수 있는 형태가 됩니다.

이떄 서버(사용자 프로세스)는 바쁜 대기를 통해 자신의 수신 버퍼를 확인하고 있는 것이 아닌, 커널이 해당 프로그램의 소켓에 데이터가 들어오는 것을 확인하기 전까지 cpu를 할당해주지 않는 상태라고 볼 수 있습니다. 이때 프로세스가 자원을 할당받을 준비가 되지 않았음을 `blocked`라는 단어를 통해 나타냅니다.

**시스템 콜**은 실제로 요청하는 방식이기도 하지만 프로그램 코드에서 특수 명령어를 통해 CPU가 커널 모드로 전환하는 것에 가깝습니다. 파일 등의 입출력이 있는 경우에는 프로그램의 메모리버퍼와 커널의 소켓/버퍼가 연결되어 데이터를 전달합니다.

## 네트워크 인터페이스
네트워크 인터페이스는 운영체제가 네트워크 연결에 사용하기 위해 사용하는 통신 지점입니다. 예를 들어 PowerShell에 `ipconfig`를 써보면 여러 유형의 인터페이스가 존재하는 것을 확인할 수 있습니다. 보통 아래와 같습니다.
- 유선 랜카드
- Wi-Fi 어댑터
- 블루투스 네트워크 장치
- VPN 어댑터
- Docker 가상 네트워크
- vEthernet
- VMWare 가상 어댑터

Linux의 경우에는 `eth0`, `ens33` 등이 존재합니다.

물리 장치와 인터페이스는 분리되어 설명될 수 있는데, 보통 랜 카드같은 실제 하드웨어를 **NIC**(`Network interface Card`) 라고 부릅니다.

일반적으로 NIC 하나에 인터페이스 하나가 존재하지만 NIC없이 인터페이스가 존재하는 경우(가상환경 등)도, NIC하나에 2개 이상의 인터페이스가 연결되는 경우(한 장치를 통해 여러 주소를 할당받는 경우) 또한 존재합니다.

앞서 설명한 `ipconfig`를 쳐보면 인터페이스의 이름과 함께 주소들이 나오는 것을 확인할 수 있는데 보통 `게이트웨이`, `IPv4`, `IPv6`, `서브넷 마스크`, `주소를 받은 DHCP 서버` 등을 확인할 수 있습니다. 여기에서 `ip주소`들은 모두 해당 인터페이스에서 자신이 보이는 형태를 설명합니다.

## VM
VM은 가상 머신(`Virtual Machine`)를 의미합니다. 이는 간단하게 생각하면 컴퓨터 안에 하나의 컴퓨터가 돌아간다고 생각할 수 있습니다. 하지만 이는 일반적인 프로세스와 다르게 실제로 하드웨어를 가상화하여 스스로의 CPU, RAM, 디스크 용량을 가지고 본인만의 운영체제(`.iso` 등 파일)를 가질 수 있습니다.

운영체제는 실제 물리 하드웨어 위에서 기존에 존재하는 `Host OS` 위에 `Hypervisor`이 돌아가며 생성되게 됩니다. (위의 설명은 *호스트 타입*(Type2)의 설명이며 *네이티브 타입*(`베어메탈` - Type1)의 경우에는 각각의 운영체제가 사용하게 됩니다.)

### VM의 네트워크
VM은 모두 자신만의 가상 네트워크 인터페이스를 가지게됩니다. VM 안에 존재하는 Guest OS는 각자 스스로의 네트워크 카드가 존재한다고 인식하며 이는 `Hypervisor`의 `[가상 스위치(브리지) / NAT / Host-only ]` 에 존재하게 됩니다.

- `NAT`: `Hypervisor`이 `NAT`의 역할을 하여 내부의 Guest OS가 외부로 사설 IP처럼 통신이 가능합니다. 포트포워딩 없이는 외부에서 가상 머신에 접근이 불가능합니다.
- `Host-only`: 이름 그대로 Host와 VM끼리만 통신하는 네트워크로 외부 인터넷과의 통신이 어렵습니다.
- `브릿지`: 가상 머신의 가상 NIC가 호스트의 PC의 물리적네트워크 카드를 직접 공유하게 됩니다. 이를 통해 이더넷과 같은 사설망에 직접적으로 연결된것과 같은 효과를 받을 수 있으며 DHCP의 대상이 됩니다. 보안 설정에 유의해야합니다.

이렇게 되면 Guest OS 안의 프로그램은 Guest OS의 가상 NIC를 통해서 Hypercisor의 가상 네트워크 장치를 통해 Host OS의 실제 네트워크 인터페이스로 가게 됩니다. 이를 통해서 최종적으로 설정에 따라 외부 네트워크와 통신이 가능하게 됩니다.

### 하이퍼바이저
컴퓨터에 필수적인 요소는 
- CPU
- RAM
- 네트워크

그리고 추가적으로 보조 디스크가 있습니다.

이렇게 생긴 하이퍼바이저는 CPU, RAM, 네트워크를 여러개로 쪼개게 됩니다.

이렇게 쪼갠 여러 자원들을 하나의 가상 서버 인스턴스(VSI)에 요구사항에 따라 할당해주게 됩니다. 이때 보조디스크(저장공간)의 경우에는 보통 하나의 파일(`.vmdk` 등)로 존재합니다.

또한 하이퍼바이저는 컴퓨터(서버) 안의 네트워크의 역할 또한 해주어 서버 인스턴스간의 요청을 네트워크를 통해 요청 및 응답을 도와주기도 합니다.

대표적인 하이퍼바이저 종류는 다음과 같이 있습니다.
- `VMWare Workstation`(Type2): 개인 무료형 윈도우/리눅스 전문 개발용 가상화 프로그램입니다. 브로드컴 소유입니다.
- `VMWare ESXi`(Type1): 기업 서버 운영 및 데이터베이스용 엔터프라이즈 가상화 솔루션입니다. 운영체제 종속성이 없습니다. 
- `VirtualBox`(Type2): 개인 학습용 오픈소스 프로그램입니다. Window, Mac, Linux에서 돌아갑니다. 오라클에서 소유합니다.
- `Hyper-V`(Type1/2): 윈도우에 기본으로 내장된 가상화 솔루션입니다. 윈도우Pro 이상이 필수입니다.

> 추가 설명을 하자면 Type1은 하드웨어 자체에 설치하는 방식입니다.

### 학습을 위한 VM
보통 개인 PC에서는 `VMWare Workstation` 등을 사용합니다. (저도 이걸 씁니다.)

학습을 하는 경우에는 보통 리눅스를 사용하고 싶은 경우(윈도우의 경우에는 자체 내장 Ubuntu 또한 존재합니다.) 또는 서버를 통해 NAT, DHCP, DNS, 방화벽, 보안, 라우팅 등의 작업을 연습해볼 수 있습니다.

IIS(윈도우 서버), Apache(리눅스) 등 또는 FTP, IGMP, 메일서버, SSH(*조만간 하고싶은 작업입니다.*) 등을 연습해볼 수 있습니다.

또한 VMware의 주요 기능중 하나인 스냅샷을 통해 복구가 가능한 형태로 컴퓨터를 마음껏 조작할 수 있습니다. 예를 들어 커널 설정, 보안실습, 방화벽, 네트워크 설정 등을 조작할 수 있습니다.

### 실무의 VM
실무에서는 보통 ESXi 또는 vSphere, vCenter과 같은 Type1 제품을 사용합니다.

일반적으로 기업용 서버는 성능이 굉장히 높기 때문에 이를 하나의 어플리케이션을 위해 사용하면 이용률이 떨어지게 됩니다. 이에 따라 하나의 서버에서 여러 어플리케이션 (DB, WAS, 테스트 서버, 파일 서버 등)

또한 학습할때 만큼은 아니지만 중요한 패치 등을 하기 전에 안전을 위해 스냅샷을 사용합니다. 보통 장기 보관의 경우에는 백업 솔류션을 사용합니다.

## 소켓 / 포트 / 포트포워딩
### 소켓
소켓은 앞서 설명했듯이 커널 메모리에서 관리하는 객체입니다. 네트워크 통신의 엔드포인트이자 그 객체를 조작하는 커널 네트워크 서브시스템을 모두 포함하여 말합니다. 보통 아래와 같은 정보가 존재합니다.
- 수신버퍼 (외부 네트워크로부터)
- 송신버퍼 (외부 네트워크)
- 지역 IP port
- 외부 IP port
- 소켓 옵션
- 연결 상태(TCP)
- wait queue (이벤트 정보)

이와 같은 객체가 커널에 존재하며 프로그램은 이 객체에 직접 접근하지 못하며 접근권한 티켓인 파일 디스크립터를 통해 커널에 요청을 하는 방식이 됩니다.

### 포트
포트는 커널이 네트워크 데이터를 어느 소켓으로 보낼지 구분하는 논리적 번호입니다.

네트워크의 3계층에는 IP주소 식별자가 존재하며 4계층에서 포트라는 개념이 생기게 됩니다. IP는 장치를 구분하는 물리(에 가까운)적인 주소 체계이며 포트는 그 장치 내부에서 프로그램들(정확히는 소켓)으로 보낼지 구분하기 위한 16비트(0~65535)의 논리적 번호입니다.

외부에서 IP를 통해 네트워크 요청이 장치에 도착하게 된다면(라우터, 네트워크 인터페이스, 스위치 등을 통해) 이것을 적절한 소켓에 보내기 위해 커널은 주소 뒷부분, 4계층 껍데기에 존재하는 포트 번호를 확인하게 되는 것입니다.

> TCP와 UDP의 포트 번호는 따로 관리됩니다.

서버는 보통 Well-knwon 포트를 열어두게 됩니다. 대표적으로 TCP의 80, 443, 1521, 3000 ,5173, 8080 등이 존재합니다. 또한 클라이언트와 통신할 때 OS가 임시 포트(`ephemeral port`)를 자동으로 골라주게 되어 통신하게 됩니다. (보통 10000 이상의 Unknown-port를 사용합니다.) 

### 포트포워딩
포트포워딩은 한 네트워크 장비나 시스템이 받은 특정 포트의 트래픽을 다른 IP/포트로 전달하도록 만드는 규칙입니다. 쉽게 이해하면 일반적으로 열어두지 않는 포트에서 외부의 요청을 받기 위해 하는 작업을 말합니다.

일반적으로 외부에서 들어오는 요청은 다음과 같은 장치 및 시스템을 거칩니다.
- 라우터
- NAT
- 방화벽
- 프록시
