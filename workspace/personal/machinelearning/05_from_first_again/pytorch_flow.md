# [Pytorch] 파이토치 플로우 다시
## 1. 데이터 준비하기
파이토치 및 인공지능 학습은 모두 데이터로부터 시작됩니다. 여기에서 데이터는 모두 확보되었다 가정하고 시작하도록 하겠습니다. 이번에는 파이토치의 Dataset/DataLoader/Subset/ImageFolder 등과 같은 데이터 객체를 위주소 말해보겠습니다.

### Dataset
우선 가장먼저 볼 것은 Dataset 계열의 클래스입니다. 이는 일반적으로 데이터를 객체 속에 저장하는것이 아닌 데이터가 존재하는 객체 또는 위치, 방법 등의 가져올 방법을 내부에 저장하는 방식으로 사용합니다.

이때 데이터의 길이인 len 또는 데이터를 가져올 경우에 동적으로 데이터의 개수를 확인하거나(파이프라인의 경우), 데이터를 db에서 로딩하는 방식을 사용합니다. 이때 중요한 속성중 하나로 transform을 통해 데이터를 뽑을 때 동적으로 데이터를 변환/증강 할 수 있는 callable transforms를 등록할 수 있습니다.

DatasetFoler 내부에는 samples와 targets가 존재하며 samples는 데이터의 경로를 나타내어 이에 접근할 수 있는 정보를 제공해주게 됩니다.

위와 같은 방식으로 여러 메모리에 적재하기 어려운 큰 데이터들을 위치 정보를 이용하여 데이터를 불러오며 사용할 수 있으며 이는 분류 데이터 외에도 해당할 수 있는 내용입니다.

### Subset
Subset 타입은 단순한 wrapper 클래스에 가까워 subset.dataset과 subset.indices를 바탕으로 원본 데이터로부터 `subset.dataset[subset.indices[0]]` 등과 같은 작업을 해줄 뿐인 객체입니다.

### DataLoader
DataLoader의 경우에는 Array 형태의 데이터이면 모두 등록할 수 있으며 shuffle, drop_last, pin_memory, num_of_worker 인자등을 이용하여 여러 상황에 대해서 효율적인 데이터 로딩을 가능하게 해줄 수 있습니다.

해당 클래스 또한 원본을 저장하는 것이 아닌 Dataset에게 데이터 로딩을 요청하여 구현하는 형태의 인터페이스 클래스에 가깝습니다.

DataLoader은 생성시에 내부적으로 shuffle, drop_last, batch_size에 맞추어 자신의 속성으로 batch 들의 인덱스를 가진 iterable 객체로 만들게 됩니다.

이는 Dataset 등의 index를 RandomSampler 또는 SequentialSampler을 이용하여 데이터가 올바른 배열을 만들어주어 이를 활용하는 형태로 사용되게 됩니다.

## 2. 신경망 설계
신경망을 만들 때에는 레이어를 어떻게 쌓을 것인가를 고민해야합니다. 이 부분에서는 활성화 함수의 선택, 선형 변환들의 종류, 피처 추출 계층의 설계, 정규화 계층, 계층의 개수 등과 같은 것들을 고려할 수 있습니다.

### 레이어의 깊이
모델을 만들 때 가장 직관적으로 보이는 요소중 하나입니다.

예를 들어 다음과 같은 과정이 한 층이라고 할 때 이를 반복하는 횟수를 설정할 수 있습니다.
1. Conv2d
2. ReLU
3. Pool

또는 경우에 따라 다음과 같은 순서를 지정할 수도 있습니다.
1. Conv2d
2. ReLU
3. Conv2d
4. ReLU
5. Pool
6. ...

이는 계층이 깊어질수록 더 복잡한 특징을 만들어 낼 수 있습니다. 첫번째 계층에서 뽑아놓은 특징들을 기반으로 그 관계를 나타내는 다른 특징, CNN의 경우에는 다른 채널간의 특징을 새롭게 재해석하는 채널들을 생성할 수도 있습니다.

하지만 소프트웨어 공학적인 부분에서 언제나 그렇듯 trade-off 관계 또한 존재합니다. 깊이가 깊어질수록 복잡한 특징 표현, 한 뉴런의 표현 범위가 증가하지만 계산량/메모리/학습 난이도가 증가할 수 있으며 **과적합 가능성이 증가**할 수 있습니다.

과적합 가능성이 높아지는 이유는 데이터를 변환시킬 수 있는 형태가 많아지면서 학습 데이터를 그대로 설명하기 쉬워지기 때문입니다.

> 이런 트레이드오프 관계를 이해하여 과적합되지 않는 선에서의 일반화를 잘하는 모델을 설계할 필요가 있습니다.

### 채널 수
채널 수 또한 하나의 레이어에서 고려해야할 요소입니다.

출력 채널수는 얼마든지 변환이 가능합니다. 개발자가 원한다면 1이 될 수 있고 9999개가 될 수 있습니다.

일반적으로 커널의 형태는 작게 설정하며 채널을 늘리는 형태를 사용하는 것이 더 빈번합니다.

그 이유는 다음과 같습니다.

```md
예를 들어 3x64x64 짜리의 기본 데이터 하나가 존재한다고 가정하겠습니다.

이를 2가지 방식으로 처리할 수 있습니다.

- 데이터를 한번에 크게 처리하기
16, 3, 3, 3 커널을 이용하게 된다면 3개의 특성을 16가지 조합으로 만들어야합니다. 이는 채널별 커널의 가중치를 모두 다르게 주어 만들 수 있지만 한 계층의 레이어만으로는 이를 모두 설명하기 어려울 수 있습니다.

- 데이터를 여러번에 걸쳐서 채널을 키우기
이에 따라 계층을 2번으로 나누어
1. 8, 3, 3, 3
2. 16, 8, 3, 3 

형태로 나누어 3개의 특성을 8개로 만들고, 8개의 특성을 다시 조합하여 16개로 만들 수 있습니다.

> 하지만 레이어가 많아질수록 당연하게도 채널 수가 달라질 수 있습니다. 전자의 경우에는 $16 x 3 x 3 x 3$ 의 파라미터를 가지지만 후자의 경우에는 $8 x 3 x 3 x 3 + 16 x 8 x 3 x 3$ 의 파라미터를 가집니다.

```

> 위와 같은 내용은 커널의 크기에도 적용되어 5x5 커널 1개와 3x3 커널 2개는 최종적으로 거의 같은 범위의 데이터를 보게되지만 실제 학습에 필요한 파라미터 비율은 25:18 을 가지게되며 3x3 커널 2개의 경우에는 ReLU와 같은 활성화 함수를 넣을 수 있어 구현에 유리하게 바뀌게 됩니다.

### Padding
패딩은 2가지 특성이 존재합니다.
- 가장자리 부분을 얼마나 살릴것인가
- 추출하면서 공간 크기를 유지 할것인가

### Stride와 Pooling
이는 공간 크기를 줄이는 대표적인 2가지 방법입니다.

Stride의 경우에는 커널의 크기를 설정하여 Conv 또는 Pool을 할 때 공간이 줄어드는 비율을 설정할 수 있습니다.

### 할성화 함수
활성함수 또한 여러가지 종류가 존재합니다.

기본적으로 많이 사용되는 것은 **ReLU**입니다.

ReLU는 계산이 단순하여 빠르고 gradient가 양수 영역에서 잘 흐른다는 장점을 가집니다. 또한 목적 또한 상대적으로 의미가 없는 음수를 없애주기 때문에 의미상 데이터의 특징을 잘 뽑게 만들 수 있습니다.

하지만 단점으로는 0과 음수 범위에서 기울기가 0이기 때문에 음수 결과가 ReLU를 거치면 역전파시에 이전 연산의 미분 결과가 항상 0이 됩니다.

> 대안으로는 LeakyreLU, GELU, SiLU 등이 있으며 이는 향후 활성화 함수 글에서 다루도록 하겠습니다.

### BatchNorm
이는 각 채널을 기준으로 분포를 재조정해주는 역할을 하게 됩니다.

이는 커널을 통한 연산에 의해 채널별 범위가 기존 정규화 범위에서 크게 벗어났을 때 이를 다시 일반적으로 -1 ~ 1 근처의 값으로 압축시켜주는 역할을 하며 과정에서 $y = \gamma x + \beta$ 를 이용하여 채널의 중요도 비중을 조정해주는 역할 또한 해줍니다. ($weight = \gamma, bias = \beta$) 

이를 통해서 학습 안정성을 높이며 큰 learning rate 사용 가능성이 높아지며 초기값에 덜 민감하지만 batch size가 너무 작으면 통계가 불안정하여 추론시에 올바른 평균과 분산을 사용하지 못할 수 있다는 위험 영역이 존재합니다.

### Dropout
이는 그 자체로 모듈로써 존재하는 계층입니다. 이는 **nn.Dropout**를 통하여 구현이 되며 대표적으로 train/eval에서 켜지고 꺼지는 모듈입니다.

이는 존재 목적 자체가 **특정 feature에 지나치게 의존하지 못하게 함**입니다. 이는 특정 feature에 과도하게 의존할 경우 추론시에 그 의존하던 feature가 불안정할 시에 제대로된 추론을 하지 못할 수 있기 때문에 사용하는 옵션입니다.

예를 들어 고양이 분류문제에서 고양이 귀의 가중치가 0.95라고 한다면 고양이 귀가 가려진 이미지가 들어올 시에 이에대한 제대로된 판별을 하지 못할 수 있다는 문제가 생길 수 있습니다.

> 또한 확률적으로 끄는 것이기 때문에 항상 중요한 정보를 잘못 규제하는 경우는 `p` 인자를 조정함으로써 타협할 수 있습니다.

### Conv 여러번 후 Pool
기본적인 `Conv`, `ReLU`, `Pool`을 하나로 묶지 않고 `Pool`의 빈도를 약간 줄이는 방식입니다.

이는 너무 빠르게 공간을 줄이게 되면 원본 세부 정보를 일찍 잃어버리기 때문입니다.

따라서 충분한 특징 추출 이후 공간 크기를 감소시킴으로써 질 높은 특징들을 만드는 기법을 말합니다.

### Resiual Connection
깊은 모델에서 중요한 기법으로 일반적인 특징추출 후 fc 계층을 통한 출력이 아닌 변환 후 기존 입력과 합쳐 반환하는 형태를 말합니다.

이는 역전파 시 기존 입력의 미분값이 1이기 때문에 학습 안정성을 높일 수 있습니다.

이는 곧 현재 입력에서 무엇을 얼마나 수정하면 되는지를 학습하라는 의미를 가지게 됩니다.

이는 10을 입력시에 15를 예측해야하는 경우에 10에서 15로 변환하는 과정을 학습해야하는 것에 반해 resiual connection은 10에 +5 하는법(변화량)을 학습할 수 있게 됩니다.

### Flatten과 Linear, Global Avaerage Pool
이는 최종적으로 정답을 수렴하기 위한 선택으로 각각의 채널에 대해서 공간의 크기를 (1, 1) 또는 이에 근접한 크기로 줄여주며 이를 Flatten 시켜 채널 개수만 fc 레이어의 입력으로 뽑아주는 형태를 만들어주게 됩니다.

이를 하지 않으면 fc계층이 너무 많은 파라미터를 학습하여 CNN의 특징 추출보다 더 큰 영향력을 가질 수 있는 문제를 해결해주게 됩니다.

다른 방식으로는 Bottleneck 방식으로 채널을 잠깐 줄였다가 다시 늘리는 방법으로 1x1 Conv를 이용하여 공간은 그대로 두되 채널 수만 줄이는 방식을 사용한 뒤 한번 3x3 Conv를 통하여 특징 재추출 후 1x1 Conv를 이용하여 다시 공간을 넓히는 기법 또한 사용할 수 있습니다.

Bottleneck를 한마디로 정의하면 채널 방향을 재정리한다고 생각할 수 있습니다.
