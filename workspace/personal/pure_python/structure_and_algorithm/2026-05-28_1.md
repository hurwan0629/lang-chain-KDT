# 시간복잡도

질문 1
arr = [10, 20, 30, 40, 50]
print(arr[3])

이건 시간복잡도가 뭐라고 생각해?

> `O(n)`이다. 모두 `0`부터 `4`까지 하나씩 찾아보면서 최악의 경우는 `n`번 찾는 것이기 때문이다. (x) (O(1)이다. 인덱스 즉시 접근)

---

질문 2
arr = [10, 20, 30, 40, 50]

for x in arr:
    print(x)

이건?

> `O(n)`이다. 항상 모두 탐색하기 때문이다.

---

질문 3
arr = [1, 2, 3, 4, 5]

for a in arr:
    for b in arr:
        print(a, b)

이건?

---

질문 4
d = {
    "apple": 3,
    "banana": 5,
    "melon": 2
}
print(d["banana"])

이건 평균적으로 시간복잡도가 뭐라고 생각해?

> `O(1)`이다. 즉시 값을 해싱을 통해 주소에 바로 접근이 가능하기 때문이다. (▲) (즉시 접근보다는 key를 해시함에 넣어 저장 위치 후보를 빠르게 찾고 값 꺼내기. 하지만 평균 `O(1)`)

---

# 배열 / 리스트

질문 1

arr = [10, 20, 30, 40, 50]

print(arr[0])
print(arr[4])

위 코드에서 arr[0], arr[4]처럼 인덱스로 접근하는 작업의 시간복잡도는?

> `O(1)`: 인덱스로 메모리 위치에 직접 접근

---

질문 2

arr = [10, 20, 30, 40, 50]

target = 40

for x in arr:
    if x == target:
        print("찾았다")

위 코드의 시간복잡도는?

> `O(n)`: 처음부터 찾을 시 최악의 경우 `n`번 순회하기 때문

---

질문 3

arr = [10, 20, 30, 40, 50]

arr.append(60)

리스트 맨 뒤에 값을 추가하는 append의 평균 시간복잡도는?

> `O(n)`: 6칸 메모리 할당 + 값 모두 복사 + `60`추가 (파이썬은 약간 다르지만 보통 이런느낌. 리스트 타입에 따라 다름.)

---

질문 4

arr = [10, 20, 30, 40, 50]

arr.insert(0, 5)

리스트 맨 앞에 값을 삽입하면 왜 비용이 커질까? 시간복잡도는?

> `O(n)`: 값을 하나씩 뒤로 땡겨서 앞에 데이터를 넣어야함

---

질문 5

arr = [10, 20, 30, 40, 50]

arr.pop()

맨 뒤 요소를 제거하는 pop()의 시간복잡도는?

> `O(1)`: 일반적인 리스트의 경우 `length` 데이터를 가지고 있어 인덱스 접근이 가능함

---

질문 6

arr = [10, 20, 30, 40, 50]

arr.pop(0)

맨 앞 요소를 제거하는 pop(0)은 왜 느릴까? 시간복잡도는?

> `O(n)`: 앞의 하나를 빼면 배열을 새로 만들거나 값들을 앞으로 땡겨와야하기 때문

질문 4

nums = [2, 7, 11, 15]
target = 9

서로 다른 두 수를 더해서 target이 되는 쌍을 찾고 싶다.
예: 2 + 7 = 9

이 문제에서 dict나 set을 어떻게 활용할 수 있을까?

> `dict`에 각 값에 대한 더했을 대 `9`가 되는 매칭 숫자 `set`를 넣는다. `{num: set}`형태로. 

> 순회하며 확인한 값들을 `set`에 넣기, target에서 뺀 값이 seen에 있으면 출력하기
```python
nums = [2, 7, 11, 15]
target = 9

seen = set()

for x in nums:
    need = target - x

    if need in seen:
        print(need, x)

    seen.add(x)
```

> left = 0, mid = 1, right = 2이 되었었으므로 `2 < nums[1]` 이기 때문에 left =0, right = 0이 되고, 또 mid = 0, nums[0] < 2 이므로 left = 0 + 1 -> right(0) < left(1)
