# 리액트

리액트는 상태에 따라 화면을 가상 DOM에서 계산해서 변경해야하는 최소한의 사항만을 변경하여 렌더링 할 수 있게 해주는 UI 라이브러리입니다.

리액트의 중요한 기술로는 다음과 같은 요소들이 존재합니다.
- `.jsx` 문법
- 컴포넌트
- `react Hook` (상태)

## 리액트의 렌더링 과정
리액트에서 사용하는 파일명이자 문법인 `.jsx`는 `JavaScript Xml`의 약자로 자바 스크립트에서 `html`을 직접 사용할 수 있는 형태입니다. 예를 들어 컴포넌트를 작성한다 하면 아래와 같은 형태가 됩니다.

```jsx
function SomeComponent() {
  const [someState, setSomeState] = useState(0)

  return (
    <div>
      <p>현재 숫자: {someState}</p>

      <button onClick={() => setSomeState(someState + 1)}>
        +1
      </button>
    </div>
  )
}
```

과 같이 작성할 수 있습니다.

여기에서 `button`태그에는 `onclick`가 아닌 `onClick`로 속성이 존재하며 변수 및 코드를 `{}`를 통해 작성이 가능한것을 확인할 수 있습니다.

이때 버튼을 누를 시 다음과 같은 과정이 일어나게 됩니다.
1. `setSomeState(someState + 1)` 동작
2. `someState` 상태 변경
3. `SomeComponent` 다시 실행
4. 새로운 JSX 갱신
핻
과 같은 작업이 반복적으로 동작하게 됩니다.

## JSX의 `{}` 문법
JSX에서 존재하는 `{}` 태그 문법은 `HTML`이 아닌 JavaScript 파일에 존재하는 별도의 문법으로 해당 문법을 `JavaScript` 표현식으로 해석하게 됩니다. 해당 자바스크립트 표현식에는 `if`/`for` 같은 문법은 작성할 수 없지만 `map()`, `a && <p>hello</p>` 와 같은 값을 반환하는 작업이 가능합니다.

또한 속성을 줄 경우에도 `src={image_link}`와 같은 형태로도 사용이 가능합니다.

위에서 설명하였듯 JSX 속성은 HTML과 별도의 문법으로 빌드 도구를 통해 JSX 속성/태그 등이 코드로 변환하여 생성하게 됩니다. 예를 들어 `button`의 `src` 속성도 사실은 인자에 가까운 값이라고 할 수 있습니다.

> 예외적으로 하이픈이 존재하는 속성의 경우에는 원래 형식을 유지합니다. (`aria-*label*` 등)

## React의 상태관리와 렌더링 무한루프
리액트는 상태를 변경하는 경우 위에서 설명한 과정과 같은 작업 이후 commit 작업 후 Effect 를 실행하여 다음 UI를 계산하게 됩니다.

이때 예를 들어 다음과 같은 상태를 가지는 경우, 무한 렌더링이 발생할 수 있습니다.

```jsx
function App() {
  const [count, setCount] = useState(0)

  setCount(count + 1)

  return <p>{count}</p>
}
```

위의 경우, `App` 컴포넌트 렌더링과 동시에 `setCount`가 호출되어 `count`가 갱신됨과 동시에 `App` 컴포넌트가 다시 렌더링 되고, 다시 `setCount`가 호출되며 무한루프가 반복하게 됩니다.

따라서 일반적으로 상태변경은 이벤트 핸들러 안에서 작업하게 됩니다.

또한 `setState(prev => prev + 1)` 등과 같은 문법을 통해 이전 상태를 기반으로 최신 상태를 안전하게 업데이트 할 수 있습니다. 이는 일반적으로 비동기로 처리되는 리액트의 상태 변화에서 `prev`를 통해 최신 값을 가져옴으로써 이벤트가 동기적으로 작업되게 할 수 있습니다.


다른 무한루프 예시로는 `useEffect` 무한루프가 존재하며 `useEffect(() => { setCount(count+1)})`을 할 시 의존성 배열 (2번째 인자)가 없기 때문에 모든 commit 뒤 실행하게 됩니다. 이는 2번째 인자를 주지 않을경우 첫 렌더링이 끝나는 시점을 의존성으로 설정하는 리액트의 특성에 의해 마운트가 끝난 후, 다시 불러와지고, `count` 상태가 변경되어 다시 렌더링이 되는 방식으로 무한루프가 반복됩니다.

또한 유의해야할 점으로는 컴포넌트 내부에서 객체를 선언할 시, 매번 렌더링되는 컴포넌트는 새로운 객체로써 같은 형태여도 다른 주소에 의해 다른 값 취급을 받을 수 있습니다. 따라서 객체등의 선언의 경우에는 가능하면 Effect 안에서 하는 것이 안전하며 실제 반응해야하는 원시 값을 의존성으로 두는것이 바람직합니다.

## Hook 변수에 대해서
예를 들어서 다음과 같은 코드가 존재합니다.

```jsx
function App() {
  const [count, setCount] = useState(0)
  const inputRef = useRef(null)

  useEffect(() => {
    console.log(count)
  }, [count])

  return <input ref={inputRef} />
}
```

위에는 `useState` > `useRef` > `useEffect` 술서대로 Hook 정보가 컴포넌트에 쌓이게 됩니다.

이를 표현해보면
```md
### App 컴포넌트의 훅
1. useState
2. useRef
3. useEffect
```
순서로 저장하며 컴포넌트를 랜더링 할 시에도 해당 순서대로 Hook를 읽게 됩니다. 이런식으로 순서를 정확하게 파악하여 내부적으로 관리하지만 훅을 조건문에 넣는 경우에는 리액트가 파악하고있는 구조와 다르게 순서가 다르게 훅을 읽을 수 있기때문에 항상 같은 순서의 훅 호출을 보장해야합니다.

### useState
`useState`는 내부적으로 `현재 상태(데이터)`, `updateQueue(다음 상태가 될 값)`, `setter(setState)`를 가지고 있습니다. 여기에서 `setter`을 선언 시 업데이트 큐에 새 값을 등록하여 다음 렌더링에서 큐를 적용하게 됩니다.

### useEffect
`useEffect`는 다음과 같은 문법을 가집니다.
```jsx
useEffect(() => {
  동작할 콜백

  return () => {
    위 콜백 작업을 정리하는 함수 (선택)
  }
}, [의존성 생태 변수 배열])
```
여기에서 React는 매 컴포넌트 렌더링마다 이전 의존성과 현재 의존성을 `Object.is` 방식을 통해 의존성이 변경되었는지 확인하는 과정을 가지며 이 값이 바뀔 경우에는 `useEffect`의 `return () => {}`를 실행 후 등록되어있는 콜백함수를 다시 동작시키게 됩니다.

이를 이용해서 API, WebSocket, 타이머, 리스너, 외부 라이브러리 등을 동기화 시킬 수 있습니다.

> `useEffect`는 주로 외부 시스템과의 동기화를 위해 사용됩니다.

### useRef
`useRef`의 경우에는 렌더링 사이에 동일한 객체를 돌려주어 해당 값이 바뀌더라도 렌더링을 예약하지 않습니다.

이를 통해 객체가 새로 생성될경우 렌더링되는 `useState`를 통한 객체생성의 약점을 보완할 수 있습니다.

### useMemo
`useMemo`의 경우, 다음과 같은 방식의 사용을 하게 됩니다.

```jsx
const filteredItems = useMemo(() => {
  return items.filter(item => item.name.includes(keyword))
}, [items, keyword])
```
여기에서 React는 `cachedValue`라는 의존성에 따라 렌더링을 하는 값들을 저장하게 됩니다.

여기에서 `useMemo`는 값 변화 이벤트를 구독하는 방식이 아닌 컴포넌트가 렌더링되는 과정에서 `useMemo`의 값에 의해서 가상 DOM을 다시 계산할지에 대한 결정을 하는 요소로 작용하게 됩니다.

### useCallback
`useCallback`의 경우에도 함수 실행결과가 아니라 함수 객체 자체를 캐싱하게 됩니다.

이는 함수(객체도)가 매 컴포넌트마다 동일한 형태의 선언이 된다 하더라도 주소가 달라 다른 객체로 인식되기 때문에 이를 캐싱하고 동일한 함수에 접근하는 방식을 사용할 수 있게 해주는 방식입니다.

하지만 함수 또한 바뀌어야하는 경우가 있기 때문에 의존성 배열을 선택적으로(없으면 마운트시점)선언을 시켜줄 수 있습니다.

## 부모와 자식 컴포넌트의 변경 전파
해당 문단이 내용은 위에서 설명한 내용과 비슷한 맥락을 가지는데 기본적으로 데이터의 경우 부모에서 자식으로 흐르게 됩니다.

이는 부모의 상태를 상속(인자로 받은)받은 자식 컴포넌트는 부모 컴포넌트가 렌더링 될 시 새로운 `props`(인자)를 가지게 되면서 자식 또한 다시 렌더링이 되게 됩니다.

또한 자식 컴포넌트가 부모를 변경 가능하게 하기 위해선 부모가 자식에게 상태를 변경 가능한 함수를 제공하는 것이 일반적입니다.

> 일단 예전에 공부하던 React를 기회가 되어 다시 이어서 공부를 하기 위해 알던 내용을 복습하긴 했지만 상태전파/렌더링 타이밍/props/children/context/redux 등에 대해서 직접 해볼 필요가 느껴져 한번 직접 작업을 더 해보려 합니다.
