# 해시맵
해시맵은 `{키: 값}`형태로 데이터를 저장할 수 있게 해주며 데이터의 접근 속도를 `O(1)`로 만들어주는 자료구조입니다.. 원리는 `set`와 같이 키를 해싱하여 나온 값의 위치에 값을 저장하는 방식입니다.

이는 속도가 빠르며 해시 충돌을 방지하기 위해 데이터가 들어갈 여유 공간을 미리 확보하게 됩니다.

일반적으로 공간의 `0.75`정도가 차게 된다면 동적으로 차지하는 공간의 크기를 넓히는 방법을 사용합니다.

## 충돌의 해결 방식
해시의 경우에도 서로 다른 2가지 값에서 같은 해시값이 나올 수 있습니다. 이런 경우에는 크게 **세로로 늘리기**와 **가로로 늘리기**방식이 존재합니다.
### 열린 주소법
열린 주소법은 특정 키가 해싱되어 나온 해시맵의 주소가 이미 차있을 때, 거기에 `n`값을 추가해서 중복되지 않은 공간에 저장하는 방식입니다. 여기에서 `n`을 정하는 방식도 `1`씩 늘리는 **선형 탐사**, `1`, `2^2`, `3^3`씩 늘리는 **제곱탐사**, 다른 해싱을 사용하는 **이중해싱**등이 있습니다.

### 체이닝
체이닝은 같은 인덱스에 들어온 데이터를 다른 곳으로 옮기지 말고 연결 리스트와 같이 이어붙이는 방식입니다.

예를 들어 `apple`, `banana`, `kiwi`가 하나의 인덱스, `0x00A2`에 들어왔다고 친다면 순서대로 `[0x00A2] -> [a_key, apple] -> [b_key, banana] -> [c_key, kiwi]`로 값을 저장하는 방식입니다.

### 동적 확장
해시맵의 인덱스 사용률이 높아질수록, 새로 들어오는 값의 충돌 확률은 점점 높아지게 됩니다. 이를 방지하기 위해 일반적으로 해시맵은 **동적 확장** 기능을 사용하여 `n%`의 사용률이 넘어간다면 해시맵을 더 키우는 방식을 사용합니다.
