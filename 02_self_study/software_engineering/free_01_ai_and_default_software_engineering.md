# 소프트웨어 공학의 설계 원칙
> 현재 저는 소프트웨어 공학이나 흐름을 들어보기는 하였지만 정확하게 알고 있는 상황은 아닙니다. 따라서 해당 글에서는 소프트웨어 공학에 익숙해지고, 용어를 한번 읽어가는 흐름을 가져보겠습니다. 주제는 `AI의 소프트웨어 공학이 일반 소프트웨어 공학과 어떤 관계인지`에 대해서입니다.

---

## 일반적인 소프트웨어 설계와 AI 설계
AI에서의 소프트웨어 설계는 기본적으로 일반 소프트웨어 공학에서 말하는 아키텍처/설계 원칙을 그대로 적용합니다.

#### 기본적인 설계 원칙
- 관심사 분리: API서버, 모델 호출, 후처리, DB 등을 분리
- 낮은 결합도: 특정 모듈 또는 인터페이스를 다른 것으로 바꾸어도 전체 코드가 잘 돌아가게 하는것
- 높은 응집도: 특정 모듈이 자신의 역할에 맞는 작업들을 모두 수행 가능하게 하는 것
- 추상화: 인터페이스를 통해 다른 모듈을 만들어도 동일한 작업을 수행 가능하게 하는 것
- 캐싱: 같은 작업 등을 재사용여 비용을 절약하는 것
- 모니터링: 에러율, 응답시간, 비용, 품질 등을 추적

> AI 서비스 또한 결국 소프트웨어일 뿐이기 때문에 기본 설계 원칙은 똑같이 적용된다. 예를 들어서 일반 서버에서 QoS를 볼때 지연, 전송률, 오류율 등과 같은 품질 기준을 따지듯, AI 서비스에서도 응답 지연, 처리량, 실패율, 비용, 품질 등을 함께 보게 됩니다.

### AI 서비스가 일반 소프트웨어와 다른 것
AI의 추론 과정은 `[입력] > [데이터] [모델] [프롬프트] [확률적] 추론 > [출력]`을 통해 이뤄지게 됩니다.

#### AI에서 추가되는 문제
- 비결성: 같은 질문에도 답이 조금씩 달라질 수 있음
- 환각: 없는 내용을 있는 것처럼 말할 수 있음
- 데이터 품질: 학습/검색 데이터가 나쁘면 결과도 나쁨
- 평가 어려움: 정답이 명확하지 않은 경우가 많음
- 모델 비용: 호출당 비용(돈, 시간, GPU)이 듭니다.
- 드리프트: 시간이 지나면 데이터/사용자 요구가 바뀌어 성능이 떨어질 수 있음
- 안정성: 개인정보, 유해 응답, 잘못된 판단 등을 고려해야함

#### 일반적인 디자인 패턴
- Strategy 패턴
- Adapter 패턴
- Facade 패턴
- Factory 패턴
- Chain of Responsibility
- Decorator

위와 같은 패턴들이 있으며, `사용자의 질문부터 입력 필터, 문서검색, 프롬프트 생성, ... 응답 검증 후 반환`까지 하게 된다면 이는 일반적인 `파이프라인 아키텍처` + `책임 분리`에 AI의 `체인 패턴`이 들어간 방식이 됩니다.

#### AI 특화 디자인 패턴
- RAG: 모델이 바로 답하지 않고, 외부 문서를 검색한 후 응답
- Prompt Template: 프롬프트를 코드처럼 재사용 가능한 템플릿으로 관리
- Model Routing: 쉬운 질문은 싼 모델, 어려운 질문은 비싼 모델로 보냄. 또는 역할에 따라 라우팅
- Fallback: 모델 호출 실패 시 다른 모델/기본 응답으로 대체
- Guardrail: 위험한 입력/출력을 필터링
- Human-in-the-loop: 중요한 판단은 사람이 최종 검토
- Evalution Loop: 모델 답변 품질을 계속 테스트하고 개선
- Vector Search: 문서를 임베딩해서 의미 기반 검색 수행

#### AI 비용과 관련된 이야기
AI는 기본적으로 일반 서비스에 비해서 자원을 더 많이 먹게될 수 있기 때문에 추가적인 자원에 대한 방법론들이 있습니다.
- 작은 모델 먼저 사용
- 컨텍스트 계산
- 프롬프트 압축
- Distillation: 큰 모델의 지식을 작은 모델에 옮김
- Batch 처리: 여러 요청을 묶어서 한번에 추론
- Streaming: 전체 답변 완료 전 일부씩 보내 체감 속도 개선
- Approximate Nearest Neighbor: 벡터 검색을 근사화해서 빠르게 검색
- Fine-tuning vs RAG: 매번 긴 프롬프트를 넣을지, 모델을 따로 학습할지 선택

> 위 내용을 통해 일반적인 `CPU`, `메모리`, `DB`, `네트워크`, `응답시간`에 더해 `토큰 비용`,`GPU/VRAM`, `모델 로딩 시간`, `추론 지연`, `임베딩 저장공간` 등 까지 고려한 작업을 하게 됩니다.

# 소프트웨어 공학 기본 뼈대
소프트웨어 공학에는 기본적으로
### 기본기
- 소프트웨어에 대한 기초: 정의, 문제, 생명주기
- 모델: 폭포수, 프로토타입, 나선형, 애자일 등
- DevOps
- 제작 과정: 요구사항 분석, 설계, 구현, 테스트, 유지보수, 품질관리, 프로젝트 관리 등
### 설계 원칙과 디자인 패턴
- 기본: 관심사분리, 응집도/결합도, SOLID 원칙, 계층형 아키텍처, MVC, Clean Architecture
- 디자인패턴: 위에서 설명하였던 디자인패턴들
- AI 확장판: Adapter, Strategy, RAG, Chain
