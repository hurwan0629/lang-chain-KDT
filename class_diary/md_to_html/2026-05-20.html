간결함

간결한 문법 덕분에 빠른 개발과 높은 생산성을 기대할 수 있다.

읽기 쉬움

사람의 언어와 비슷한 형태를 가지며, CPython 기준으로는 소스 코드를 바이트코드로 컴파일한 뒤 인터프리터가 실행한다.

넓은 생태계

데이터, 웹, 인공지능, 자동화, 스케줄링 등에서 검증된 라이브러리를 활용할 수 있다.

codex의팁: 인터프리터 언어를 조금 더 정확히 보기

파이썬을 “한 줄씩 읽어서 실행한다”라고 설명하면 입문 단계에서는 이해하기 쉽지만, 실제 CPython은 먼저 .py 코드를 바이트코드로 바꾸고 그 바이트코드를 파이썬 가상 머신이 실행한다.

그래서 문법 오류는 실행 전에 잡히는 경우가 많고, 실행 중에 도달한 코드에서 런타임 오류가 발생할 수 있다.

단점

기계에 직접 최적화된 코드 형태가 아니기 때문에 순수 파이썬으로 작성한 CPU 중심 로직은 C, Assembly에 비해 실행 속도가 낮을 수 있다.

codex의팁: 파이썬이 항상 느린 것은 아님

파이썬 자체 반복문은 느릴 수 있지만, NumPy, OpenCV, PyTorch 같은 라이브러리는 내부 핵심 연산이 C, C++, CUDA 등으로 구현된 경우가 많다. 그래서 데이터 분석과 AI 분야에서는 파이썬을 “빠른 연산을 직접 하는 언어”라기보다 “빠른 라이브러리를 연결하고 조율하는 언어”로 보는 편이 정확하다.

개발자의 한계가 될 수 있는 부분

개발자는 도메인 지식이 없기 때문에 해당 분야의 전문가만큼 효율적인 로직을 짜는 것이 어려운 경우가 많다.

실제로는 과학자가 AI에 먼저 관심을 가졌지만, 현재는 과학자가 아닌 개발자들이 AI를 개발하는 경우가 많아졌다.

이런 흐름에서 어떤 교수님은 개발자가 아니라 본인이 직접 만드는 편이 더 낫겠다고 생각했고, 배우기 쉬운 파이썬이 인기를 얻게 된 사례도 있다.

많은 언어를 배우는 것도 좋지만, 선생님의 추천 언어는 다음과 같다.

  • Python
  • JavaScript 또는 TypeScript

IT계열의 취업

어느 직군이든 신입은 어렵지만, 선생님은 IT 직군이 그나마 낫다고 하셨다.

인문계열은 학벌이나 레벨을 많이 보는 편이지만, 이공계열에서는 학벌이나 성별보다 실력을 더 많이 보기 때문에 유리한 면이 있다.

경력이 우대받는 것은 사실이지만, IT는 경력이 우대받는 폭이 훨씬 크다.

왜일까?

경력직의 경우에는 포폴이 괜찮은 사람을 말한다. 개발에서는 경쟁이 매우 심하고 실무 경험에 따라 개발 속도가 크게 달라지기 때문이다.

예를 들어 A사와 B사의 팀 구성에 따라 경쟁 구도가 완전히 달라질 수 있다.

반대로 말하면 경력과 포폴이 쌓이면 강력한 경쟁력이 될 수 있다. 단, 잘하는 개발자일 때의 이야기다.

OS란? - Operating System

컴퓨터, 냉장고 등 장치를 다루며 운영해주는 시스템을 말한다.

본인(허완)은 사용자와 프로그램이 컴퓨터 또는 기기를 다룰 수 있게 해주는, 하드웨어 바로 위에 존재하는 소프트웨어라고 생각한다.

프로그래밍 언어에서 힘든점

요즘에는 LLM이 워낙 잘 찾아주지만, 과거에는 지금보다 에러를 찾는 능력이 훨씬 중요했다.

과거에는 구글이 강력한 도구였고, 공부를 하거나 에러를 찾을 때 많이 쓰였다. Swift, Go처럼 일반 단어와 겹치는 코딩 용어가 있어 문제를 찾는 데 시간이 걸리기도 했다.

AI에 관하여

AI는 기본적으로 학습 데이터와 사용자가 제공한 입력 컨텍스트를 바탕으로 답을 만들기 때문에 비즈니스 환경, 특히 보험이나 금융 분야에서는 온라인 LLM 사용이 제한될 수 있다.

따라서 스스로 해결하는 능력을 기를 수 있어야 한다.

codex의팁: LLM을 쓸 때 조심할 점

LLM은 모르는 내용을 그럴듯하게 말할 수 있고, 최신 정보나 회사 내부 규칙은 모를 수 있다. 업무에서 쓸 때는 입력한 정보가 외부 서비스로 나가도 되는지, 답변 근거가 검증 가능한지, 실제 코드나 문서와 맞는지를 확인해야 한다.

파일의 형태

파이썬은 보통 두 가지 파일 형태를 사용한다.

.py

파이썬으로 작성된 일반적인 소스코드다. 순차적으로 실행되며 완성된 프로그램을 만들 때 사용한다.

함수와 클래스를 통해 구조와 유지보수에 유리하다.

.ipynb

Jupyter Notebook 형식의 파일이다. 코드를 셀로 나누어 노트와 연구를 하기 위해 사용한다.

데이터 분석, 머신러닝 실험, 시각화, 교육, 강의 자료 작성 등에 쓰인다.

수업 활용

당분간은 노트 필기를 위해 .ipynb를 쓰게 될 것이라고 한다.

codex의팁: .py와 .ipynb를 고르는 기준

.ipynb는 실험, 설명, 시각화, 수업 필기처럼 중간 결과를 보며 진행할 때 편하다. 반대로 실제 서비스 코드, 반복 실행할 스크립트, 테스트가 필요한 코드는 .py로 정리하는 편이 유지보수에 좋다.

다운 링크와 환경 준비

이번 과정에서는 파이썬 라이브러리의 안정성을 위해 아래 버전을 사용한다.

  • Windows 파이썬 3.12.10 64-bit 다운
  • 파이썬 3.12.10 링크
  • VSCode

선생님은 3.12.7 버전으로 실행하셨다.

윈도우에서 설치할 때 초반에 나오는 Add python.exe to PATH 옵션을 눌러주어야 한다.

codex의팁: Python 버전 표기와 PATH

현재 링크는 Python 3.12.10 설치 파일을 가리킨다. 1.12.10은 오타로 볼 수 있다. PATH는 터미널에서 python 또는 py 명령을 바로 찾게 해주는 환경 변수다.

설치 후에는 PowerShell에서 python --version 또는 py --version으로 설치 버전을 확인하면 된다.

VSCode

VSCode는 텍스트 편집 툴로, 언어 환경이라기보다는 코드를 작성하는 공간이다. 러키 메모장 정도로 볼 수 있다.

VSCode는 플러그인을 통해 언어에 맞는 편집 기능을 제공한다. 파이썬의 경우 Microsoft의 Pylance, 코드 정렬을 위한 Black Formatter 등을 Extensions에서 설치할 수 있다.

VSCode는 내부 터미널 기능도 제공하여 추가 작업을 편하게 진행할 수 있다.

codex의팁: VSCode와 Python은 역할이 다름

VSCode는 코드를 작성하고 실행을 편하게 돕는 편집기다. 실제 파이썬 코드를 실행하는 것은 설치된 Python 인터프리터이며, VSCode의 Python 확장과 Pylance는 자동완성, 오류 표시, 실행 버튼, 디버깅 같은 개발 편의 기능을 제공한다.

가상환경 팁

파이썬을 사용할 때 venv라는 가상환경을 사용하면 프로젝트별로 라이브러리를 분리해서 관리할 수 있다. 또한 외부 공유와 재현도 편해진다.

python -m venv .venv로 만들었다면 폴더 이름은 .venv다. 그래서 윈도우 PowerShell 활성화 경로는 보통 .\.venv\Scripts\Activate.ps1가 된다.

  1. 프로젝트 폴더 만들기
  2. 프로젝트 폴더에 들어가기
  3. python -m venv .venv 작성하기
  4. 폴더에서 .\.venv\Scripts\Activate.ps1를 PowerShell로 실행하기. 윈도우 기준이며, macOS나 Linux는 source .venv/bin/activate를 사용한다.
  5. 필요한 라이브러리를 pip install [라이브러리 명]으로 설치하기
  6. pip freeze > requirements.txt로 다른 사람이 같은 라이브러리를 사용할 수 있게 만들기

pip freeze > requirements.txt는 현재 가상환경에 설치된 모든 패키지와 버전을 고정해서 기록한다. 재현성은 좋지만, 불필요한 패키지도 같이 들어갈 수 있으니 새 프로젝트에서는 필요한 패키지만 설치한 직후에 만드는 것이 좋다.
